# リンクの形式

この文書は、PDF 内の位置を指す `pdf-deeplink` のリンク形式（バージョン 1）を規定する。リンクは URL のパス `/view` とクエリパラメータからなり、対象の PDF、発行時点のハッシュ値、ページ上の矩形、および任意のページラベルと検索用テキストを表す。

アプリケーションの導入、設定、操作手順については、[README](../README.md) を参照のこと。

## リンクの構成

リンクの URL のパスは `/view` とする。クエリ文字列のパラメータは次のとおり。

| 名前     | 必須 | 内容                                                                                               |
| -------- | ---- | -------------------------------------------------------------------------------------------------- |
| `v`      | 任意 | リンク形式のバージョン。バージョン 1 では `1`                                                      |
| `src`    | 必須 | 取得元とアイテムの識別子。`zotero:` の後に 8 文字の英大文字・数字の添付キーを指定する              |
| `sha256` | 必須 | リンク発行時点の PDF の SHA-256。英小文字の 16 進数 16〜64 桁                                      |
| `rects`  | 必須 | 対象ページと矩形の配列。全ページ合計で 1〜64 個                                                    |
| `label`  | 任意 | 誌面のページラベル。複数ページにまたがるリンクでは範囲（例: `iv–v`）。64 文字以内                  |
| `q`      | 任意 | 検索用テキスト（本文の引用や図表のタイトルなど、該当箇所の検索と出典に用いる文字列）。200 文字以内 |

`label` と `q` の文字数は、Unicode のコードポイント数で数える。複数ページにまたがるリンクの `label` では、開始ページと終了ページのページラベルを en ダッシュ（`–`、U+2013）で結ぶ。

### rects の表記

`rects` は 1 個以上の矩形を `_` で連結した文字列であり、各矩形は `x,y,幅,高さ` で表す。

ページが切り替わる最初の矩形の前には `<ページ番号>:`（1 始まり）を付ける。`<ページ番号>:` が付いた矩形から、次の `<ページ番号>:` の直前までがそのページの矩形として解釈される。先頭の矩形には必ず `<ページ番号>:` を付け、ページ番号は重複なく昇順に並べる。ビューアでリンクを開くと、先頭のページにある最初の矩形の位置へ移動する。

説明用の `rects` の例を次に示す（12 ページの矩形 1 個と、13 ページの矩形 2 個を表す）。

```text
rects=12:72,700,240,18_13:72,60,240,40_72,100,180,18
```

### 座標系

`rects` の座標は、PDF のページに設定された回転（`/Rotate`、時計回り）と表示領域（CropBox）を適用した表示上のページの左上を原点とし、右方向を x 軸の正、下方向を y 軸の正とする。座標の単位には PDF のユーザー空間の単位を用いる（通常は 1/72 インチ。`/UserUnit` が設定された PDF では変わりうる）。

ページ画像を対象とする処理（画像上での範囲の特定や範囲の切り出し）で表示上の座標をそのまま利用できるよう、表示上のページを基準としている。

PDF のユーザー空間（左下原点、y 軸は上向き）との相互変換には、PDF.js の `PageViewport` と同じ式を用いる。ページの表示領域を `viewBox = [x1, y1, x2, y2]`、回転角を `r = ((rotation mod 360) + 360) mod 360`（0、90、180、270 のいずれか。たとえば `-90` は `270` へ正規化される）とするとき、ユーザー空間の点 `(x, y)` と表示上の点 `(dx, dy)` の変換式は次のとおり。

| 正規化後の回転角 `r` | ユーザー空間 `(x, y)` から表示上 `(dx, dy)` | 表示上 `(dx, dy)` からユーザー空間 `(x, y)` |
| -------------------- | ------------------------------------------- | ------------------------------------------- |
| `0`                  | `(x - x1, y2 - y)`                          | `(dx + x1, y2 - dy)`                        |
| `90`                 | `(y - y1, x - x1)`                          | `(dy + x1, dx + y1)`                        |
| `180`                | `(x2 - x, y - y1)`                          | `(x2 - dx, dy + y1)`                        |
| `270`                | `(y2 - y, x2 - x)`                          | `(x2 - dy, y2 - dx)`                        |

ユーザー空間の対角の 2 点 `a`、`b` からリンクの矩形 `[x, y, 幅, 高さ]` を求めるときは、両点を表示上の座標 `(ax, ay)`、`(bx, by)` へ変換し、`[min(ax, bx), min(ay, by), |ax - bx|, |ay - by|]` を算出する。リンクの矩形 `[x, y, 幅, 高さ]` からユーザー空間の境界 `[x1, y1, x2, y2]` を求めるときは、`(x, y)` と `(x + 幅, y + 高さ)` をユーザー空間の座標 `(ax, ay)`、`(bx, by)` へ変換し、`[min(ax, bx), min(ay, by), max(ax, bx), max(ay, by)]` を算出する。

## 生成の規則

生成する URL のパスは `/view` とする。クエリパラメータは `src`、`sha256`、`rects` の順に並べ、値がある場合は `label`、`q` をこの順で続ける。

各パラメータの生成規則は次のとおり。

- `v`: バージョン 1 では省略する。
- `src`: `zotero:<8 文字の英大文字・数字>` をそのまま出力する。
- `sha256`: リンク発行時点の PDF のバイト列から計算した SHA-256（英小文字の 16 進数）の先頭 16 桁を出力する。
- `rects`:
    - 各座標値（`x`、`y`、幅、高さ）は小数第 1 位に丸める（小数第 2 位が 5 の場合は正の無限大方向へ丸める）。整数になる場合は小数点以下を省略し、負の 0 は `0` として出力する。
    - 丸めた結果が `0` になる幅と高さは `0.1` に補正する。
    - ページごとに先頭の矩形だけに `<ページ番号>:` を付け、すべての矩形を `_` で連結して出力する。
- `label`: 空の値または未指定の場合は省略する。64 文字（Unicode のコードポイント数）を超える場合は先頭 64 文字に切り詰める。
- `q`: 空の値または未指定の場合は省略する。200 文字（Unicode のコードポイント数）を超える場合は先頭 200 文字に切り詰める。

符号化: `src`、`sha256`、`rects` は符号化せずに出力する。`label` と `q` は `application/x-www-form-urlencoded` 形式（半角空白は `+`、非 ASCII 文字や `;` `,` `:` などの記号はパーセントエンコード）で符号化する。

説明用のリンク例を次に示す（`<16 桁の SHA-256>` と `<符号化済みの検索用テキスト>` はプレースホルダであり、実際の生成時は対応する値に置き換える）。

```text
/view?src=zotero:ABCD1234&sha256=<16 桁の SHA-256>&rects=12:72,700,240,18_13:72,60,240,40_72,100,180,18&label=iv%E2%80%93v&q=<符号化済みの検索用テキスト>
```

## 解釈の規則

パスが `/view` の URL を対象とし、クエリ文字列を `application/x-www-form-urlencoded` 形式として復号したうえで検証する。定義されたパラメータ（`v`、`src`、`sha256`、`rects`、`label`、`q`）のうち、同じ名前のパラメータが複数回現れる場合はエラーになる。

各パラメータの検証規則は次のとおり。いずれかに違反する場合はエラーになる。

- `v`: 任意。省略または `1` だけを受け付ける。空の値や `1` 以外はエラーになる。
- `src`: 必須。`zotero:` の後に 8 文字の英大文字・数字（`A`〜`Z`、`0`〜`9`）が続く形式だけを受け付ける。
- `sha256`: 必須。英小文字の 16 進数（`0`〜`9`、`a`〜`f`）で 16〜64 桁の値だけを受け付ける。
- `rects`: 必須。`_` で区切られた矩形の総数が全ページ合計で 1〜64 個であり、次の条件をすべて満たす値だけを受け付ける。
    - ページ番号: 先頭の矩形に `<ページ番号>:` が付いており、各ページ番号は 1〜100000 の整数（先頭の `0` を含まない）で重複のない昇順であること。各ページ番号には 1 個以上の矩形が続くこと。
    - 座標: 各矩形は `,` 区切りの 4 個の数値（`x,y,幅,高さ`）で構成され、各数値は 10 進数（先頭の `-` は省略可、整数部の後に小数点と小数部を続けてよい。指数表記や `+` は不可）であること。4 個とも絶対値が 100000 以下であり、幅と高さは正の数（`0` より大きい）であること。`x` と `y` には負の数を指定でき、負の 0（`-0` や `-0.0`）は `0` として解釈される。
- `label`: 任意。空の値は省略とみなされる。64 文字（Unicode のコードポイント数）を超える場合はエラーになる。
- `q`: 任意。空の値は省略とみなされる。200 文字（Unicode のコードポイント数）を超える場合はエラーになる。

### PDF のバージョンの照合

解釈で得た `sha256`（16〜64 桁）が、対象 PDF のバイト列から計算した SHA-256（英小文字 64 桁）の先頭と一致すれば、同じバージョンとみなす。

一致しない場合は、PDF が更新または差し替えられて `rects` の座標がずれている可能性がある。その場合、`rects` のページ番号、`label`、`q` が該当箇所を確認する手がかりになる。

## テストベクタ

リンクの解釈、生成、PDF のバージョンの照合、および座標変換の期待値は、言語に依存しない JSON 形式で [`spec/`](../spec/) に定義されている。別の言語で実装する場合も、これらのテストベクタで検証できる。

- [`spec/link-vectors.json`](../spec/link-vectors.json): クエリの解釈（`parse`）、生成（`format`）、PDF のバージョンの照合（`sameVersion`）
- [`spec/geometry-vectors.json`](../spec/geometry-vectors.json): 回転ごとの座標変換（`toLinkRect`、`toUserSpace`）。同ファイルに含まれる矩形の結合（`mergeLineRects`、`mergeSelectionRects`）はリンク形式の規則ではなく、このアプリケーションがリンクを発行する際の参考として定義されている
