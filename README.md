# pdf-deeplink

PDF 上で選択した文章や矩形の範囲を指すリンクを発行し、リンクを開くと該当箇所へ移動して範囲を一時的に強調表示する Web アプリケーションである。PDF は Zotero Web API v3 互換の HTTP サーバから読み取りのみで取得し、PDF ファイルにも取得元にも書き込まない。リンクはサーバに保存せず、URL のパスとクエリだけで対象の PDF、版、ページ、範囲を表す。

このリポジトリは、ブラウザで動作するビューア、取得元への問い合わせとビューアの配信を担う Node.js サーバ、およびリンク形式の仕様とテストベクタを収めている。リンクの形式や座標系の仕様は [リンクの形式](docs/link-format.md) を参照のこと。

## 機能

### リンクの発行

ビューアのツールバーで選択方法を切り替え、1 ページ内の対象を選んでポップアップからリンクを発行する。

- 「文章」モード（初期状態）: 本文をドラッグして選択すると、同じ行の隣接する矩形が結合され、選択文の先頭 100 文字が「目印」の初期値として入力される
- 「範囲」モード: ツールバーで「範囲」を選び、ページ上でドラッグして矩形を囲む（幅または高さが 2 PDF ポイント未満の矩形は無視される）

ポップアップでは目印（引用、図表番号、メモ。200 文字以内）を編集でき、「リンクをコピー」を選ぶと利用中の環境のオリジンを含む URL がクリップボードへコピーされる。クリップボードへの書き込みに失敗した場合は、コピー用のダイアログが表示される。ページをまたぐ選択や、結合後の矩形が 64 個を超える選択からはリンクを発行できない。

### 該当箇所の強調表示

発行済みのリンクを開くと、ビューアは取得した PDF の版を照合したうえで該当ページの指定位置へスクロールし、対象の矩形を 8 秒間強調表示する。リンクに `src` 以外の不正なパラメータが含まれる場合は、警告バナーを表示したうえで文書だけを開く。

### PDF の版の照合

ビューアは取得した PDF のバイト列から SHA-256 を計算し、リンクの `sha256` と照合する。一致しない場合（リンクの作成後に PDF が差し替えられた場合）は古い範囲を強調表示せず、警告バナーに作成時のページ（誌面のページラベルがある場合はその表記）と目印を表示する。利用者はバナー上のボタンから、そのページへの移動と、目印がある場合は本文内検索を実行できる。`sha256` が一致してもリンクのページ番号が PDF の総ページ数を超える場合は、範囲を適用せず、ページが存在しない旨の警告バナーとページ移動・検索のボタンを表示する。

### 出典のコピー

範囲選択時のポップアップ、または有効なリンクで開いた際にツールバーへ表示される「出典をコピー」から、書誌情報と箇所をまとめた文字列をコピーできる。著者（3 名以上の場合は先頭の 1 名に「ほか」を付加）と発行年、タイトル、掲載誌、DOI（`https://doi.org/` 形式）、ページ（誌面のページラベルまたはページ番号）、目印のうち値がある項目をまとめて出力する。書誌情報が取得できない場合は、ページと目印のみを出力する。

### 文献の一覧

トップ画面（`/`）の文献一覧は、リンクを発行する PDF を開くための補助機能である。PDF が添付された文献の検索、並び替え、表示件数の切り替え、ページ送りに対応し、表示条件は URL に保持される。一覧から文献を選ぶか、発行済みのリンクを開くと、ビューア画面（`/view`）が開く。

## 導入

### 取得元 API の要件

取得元には Zotero Web API v3 互換の HTTP サーバを用いる。接続先は平文の HTTP（`http://`）または Unix ドメインソケットに限られ、HTTPS および認証ヘッダの送信には対応していない。サーバはすべての要求に `Zotero-API-Version: 3` ヘッダを付け、取得元へ次の `GET` 要求を送る。

| 要求                                                                                                                           | 期待する応答と用途                                                                                                                                                                                                                                                                                                     |
| ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET <API のパス>/items/top?start=<開始位置>&limit=100&sort=<項目>&direction=<方向>`（検索語がある場合は `q=<検索語>` を付与） | 状態コード `200` とアイテム配列の JSON。一覧の取得に用いる。総件数は `Total-Results` ヘッダから読む（数値でない場合は取得件数が 100 未満の時点で終端とみなす）。上位アイテム自身が PDF 添付であるか、`links.attachment` が PDF（`application/pdf`）かつ `/items/<8 文字キー>` 形式の `href` を指すものだけを対象とする |
| `GET <API のパス>/items/<アイテムキー>`                                                                                        | 状態コード `200` とアイテムの JSON。添付アイテムが PDF であることを確認し、`data.parentItem` に有効なアイテムキーがある場合は同じ経路で親アイテムも取得して書誌に用いる                                                                                                                                                |
| `GET <PDF_DEEPLINK_ZOTERO_FILE_PATH>`（`{key}` を添付アイテムキーへ置換）                                                      | 状態コード `200` と PDF のバイト列。リダイレクトには追従せず、`200` 以外の応答はエラーとして扱う                                                                                                                                                                                                                       |

`sort` には `dateModified`、`dateAdded`、`title`、`creator`、`date` のいずれかが、`direction` には `asc` または `desc` が渡される。アイテムキーは英大文字と数字の 8 文字で構成される。

一覧の取得時、1 つの上位アイテムに複数の PDF が添付されていても、代表の添付（`links.attachment`）の 1 件だけが表示される。サーバは検索条件に合う上位アイテムを 100 件ずつ最大 5,000 件まで取得してから PDF のあるものへ絞り込み、総件数とページを求める。5,000 件を超える場合は一覧画面へ一部の文献だけを対象としている旨が表示される。絞り込み結果は検索語、並び順、昇降順の組み合わせごとに 60 秒間（最大 16 件）メモリに保持され、同じ条件でのページ送りでは取得元へ再問い合わせされない。利用者が要求を中断した場合、取得元への問い合わせも打ち切られる。

### 環境変数

サーバの設定は環境変数で指定する。

| 変数                             | 既定値                   | 内容                                                                                                                                                      |
| -------------------------------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PDF_DEEPLINK_ZOTERO_FILE_PATH`  | なし（必須）             | PDF 本体を返す経路。`{key}` を含めること（例: `/files/{key}`）。未指定または `{key}` を含まない場合は起動に失敗する                                       |
| `PDF_DEEPLINK_ZOTERO_ENDPOINT`   | `http://127.0.0.1:23119` | 取得元の接続先。`http://<ホスト>[:<ポート>]`（パス不可、ポート省略時は `80`）または `unix:<ソケットのパス>`                                               |
| `PDF_DEEPLINK_ZOTERO_API_PATH`   | `/api/users/0`           | 取得元 API のベースパス（末尾の `/` は自動で除かれる）                                                                                                    |
| `PDF_DEEPLINK_ZOTERO_TIMEOUT_MS` | `30000`                  | 取得元への 1 回の問い合わせのタイムアウト（ミリ秒、正の整数）                                                                                             |
| `PDF_DEEPLINK_LISTEN`            | `127.0.0.1:8787`         | 待ち受け先。`<ホスト>:<ポート>` または `unix:<ソケットのパス>`。Unix ソケット指定時は既存のソケットファイルを削除し、待ち受け後にモード `0660` を設定する |
| `PDF_DEEPLINK_ALLOWED_HOSTS`     | `localhost,127.0.0.1`    | 許可する `Host` ヘッダのホスト名（カンマ区切り、大文字小文字は区別しない）                                                                                |
| `PDF_DEEPLINK_STATIC_DIR`        | リポジトリ直下の `dist/` | ビルド済みビューアの配信元ディレクトリ                                                                                                                    |

サーバは `GET` 要求のみを受け付け、それ以外の HTTP メソッドには HTTP 405 を返す。`/app/` 以外のパスは `PDF_DEEPLINK_STATIC_DIR` から静的ファイルとして配信され、`/` と `/view` は該当ファイルがない場合に `index.html` を返す。`assets/` 配下には `Cache-Control: public, max-age=31536000, immutable`、その他の静的ファイルには `Cache-Control: no-cache` が付与される。`PDF_DEEPLINK_STATIC_DIR` に `index.html` が存在しない場合、静的ファイルの配信は無効になり、`/app/` 以外の要求には HTTP 404 が返る。

### 接続元の制限

サーバは、次のいずれかに該当する要求を HTTP 403 で拒否する。

- `Host` ヘッダがない、またはポート番号を除いたホスト名が `PDF_DEEPLINK_ALLOWED_HOSTS` に含まれない要求
- `Sec-Fetch-Site` ヘッダが付与されており、その値が `same-origin` または `none` 以外の要求（`Sec-Fetch-Site` ヘッダがない要求は拒否しない）

これらの制限により、悪意のある Web ページが DNS リバインディングやクロスサイト要求を通じてサーバを呼び出し、ライブラリの内容を読み取ることを防ぐ。また、PDF 本体を返す `/app/documents/<src>/file` には `Content-Disposition: attachment`、`Content-Security-Policy: default-src 'none'; sandbox`、`Cache-Control: no-store`、`X-Content-Type-Options: nosniff` が付与され、PDF の URL を直接開いた際に同一オリジン上でインライン表示されないよう保護されている。

このサーバは利用者の認証を行わない。単独で利用する場合は、ループバックアドレスまたは Unix ドメインソケットで待ち受けること。ネットワーク越しに公開する場合は、認証を担うリバースプロキシの背後に配置し、利用者がアクセスするホスト名を `PDF_DEEPLINK_ALLOWED_HOSTS` に加えたうえで、リバースプロキシからその `Host` ヘッダを渡すこと。

### 起動手順

#### コンテナでの起動

開始条件: Docker などのコンテナランタイムを利用でき、コンテナから取得元の HTTP サーバへ到達できること。

1. コンテナイメージをビルドする（ビルド工程内でテスト、型検査、ビューアのビルドが実行される）。

    ```sh
    docker build -t pdf-deeplink .
    ```

1. コンテナを起動する。次の説明用のコマンド例では、`<取得元のホスト>`、`<ポート>`、および `/files/{key}` を利用環境の取得元に合わせて置き換えて実行すること。コンテナ外から接続できるよう `PDF_DEEPLINK_LISTEN` には `0.0.0.0:8787` を指定する。

    ```sh
    docker run --rm -p 127.0.0.1:8787:8787 \
        -e PDF_DEEPLINK_LISTEN=0.0.0.0:8787 \
        -e PDF_DEEPLINK_ZOTERO_ENDPOINT=http://<取得元のホスト>:<ポート> \
        -e PDF_DEEPLINK_ZOTERO_FILE_PATH='/files/{key}' \
        pdf-deeplink
    ```

1. 標準出力に `listening on http://0.0.0.0:8787` が出力されたら、ブラウザで `http://127.0.0.1:8787/` を開き、文献の一覧が表示されることを確認する。

注意: コンテナ内の `127.0.0.1` はコンテナ自身を指す。ホスト上で動作する取得元へ接続する場合は、利用中のコンテナ環境でホストへ到達できるアドレスを指定するか、Unix ドメインソケットをマウントして `PDF_DEEPLINK_ZOTERO_ENDPOINT` に `unix:<パス>` を指定すること。取得元への接続失敗やエラーはサーバの標準エラー出力へ記録され、画面にもエラーが表示される。

#### Node.js での起動

開始条件: [mise](https://mise.jdx.dev/)（`mise.toml` に定義された Node.js を用いる）または `package.json` の `engines` に適合する Node.js を利用でき、取得元の HTTP サーバへ到達できること。`mise` を用いない場合は、手順内のコマンドから `mise exec --` を省いて実行する。

1. 依存パッケージを導入し、ビューアを `dist/` へビルドする。

    ```sh
    mise exec -- npm ci
    mise exec -- npm run build
    ```

1. `PDF_DEEPLINK_ZOTERO_FILE_PATH` を指定してサーバを起動する。次の説明用のコマンド例では、`/files/{key}` を取得元の経路に合わせて置き換えること。取得元の接続先や待ち受け先を既定から変える場合は、対応する環境変数もあわせて指定する。

    ```sh
    PDF_DEEPLINK_ZOTERO_FILE_PATH='/files/{key}' mise exec -- node server/main.ts
    ```

1. 標準出力に `listening on http://127.0.0.1:8787`（既定の待ち受け先の場合）が出力されたら、ブラウザで `http://127.0.0.1:8787/` を開き、文献の一覧が表示されることを確認する。

注意: `npm run build` を実行せずに起動すると、`dist/index.html` が存在しないためビューアは配信されず、`/app/` 以外の要求は HTTP 404 となる。取得元への接続失敗やエラーはサーバの標準エラー出力へ記録され、画面にもエラーが表示される。

## 開発

### リポジトリ構成

| ディレクトリ | 役割                                                                                                                                                        |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `web/`       | ブラウザ上で動作する一覧画面と PDF ビューア。PDF.js で PDF を描画し、範囲の選択、リンクの発行と解釈、強調表示、出典のコピーを担う                           |
| `server/`    | 取得元へ問い合わせる HTTP API（`/app/documents`、`/app/documents/<src>`、`/app/documents/<src>/file`）と、ビルド済みビューアの静的配信を担う Node.js サーバ |
| `shared/`    | ビューアとサーバが共用するリンクの解析・生成と座標変換                                                                                                      |
| `spec/`      | 言語に依存しないリンク形式と座標変換のテストベクタ（`link-vectors.json`、`geometry-vectors.json`）                                                          |
| `docs/`      | リンク形式の仕様（[リンクの形式](docs/link-format.md)）                                                                                                     |

### 開発環境の準備

開始条件: [mise](https://mise.jdx.dev/)、[uv](https://docs.astral.sh/uv/)、および Bash を利用できること。Node.js は `mise.toml` の定義から解決される（`.nvmrc` にも同じメジャー版が定義されている）。

次のコマンドで、依存パッケージの導入と Git フックの登録を実行する。

```sh
mise exec -- bash scripts/setup.sh
```

`scripts/setup.sh` は `npm install`、`uv tool install pre-commit`、および `pre-commit` と `pre-push` の Git フック登録を実行する。コミット時には秘密値の検出（gitleaks）、Markdown・JSON・YAML・TypeScript の整形とリント、改行コードやマージ競合の検査が、push 時には型検査とテストが自動で実行される。

### 開発サーバの起動

ビューアの開発サーバ（Vite）は `http://127.0.0.1:5173/`（ポート固定）で待ち受け、`/app` への要求をバックエンドサーバへ中継する。また、PDF.js が実行時に取得する CMap、標準フォント、Wasm、ICC プロファイルを `node_modules/pdfjs-dist` から `/pdfjs/` 配下で配信する（`npm run build` では同じ構成が `dist/pdfjs/` へ複製される）。

開始条件: 依存パッケージを導入済みであり、取得元の HTTP サーバへ到達できること。

1. 1 つ目の端末でバックエンドサーバを起動する。次の説明用のコマンド例では、`/files/{key}` を取得元の経路に合わせて置き換えること。

    ```sh
    PDF_DEEPLINK_ZOTERO_FILE_PATH='/files/{key}' mise exec -- npm run dev:server
    ```

1. 2 つ目の端末でビューアの開発サーバを起動する。

    ```sh
    mise exec -- npm run dev:web
    ```

1. ブラウザで `http://127.0.0.1:5173/` を開き、文献の一覧が表示されることを確認する。

注意: `PDF_DEEPLINK_LISTEN` を既定（`127.0.0.1:8787`）から変更した場合は、`dev:web` にも同じ `<ホスト>:<ポート>` を指定すること。Vite の中継先は `http://` 形式で構成されるため、開発時の中継では `PDF_DEEPLINK_LISTEN` に Unix ソケットを指定できない。

### 検査

コミットおよび push のフックと同等の検査は、次のコマンドで手動実行できる。

```sh
uvx pre-commit run --all-files
mise exec -- npm run typecheck
mise exec -- npm test
```

個別の検査やビルドには、次の npm スクリプトを利用できる。

- `npm run lint`: ESLint による TypeScript の検査
- `npm run format:check`: Prettier による TypeScript の整形確認
- `npm run format`: Prettier と ESLint による TypeScript の自動整形
- `npm run build`: ビューアと PDF.js 実行時ファイルの `dist/` へのビルド

`main` ブランチへの pull request では、`.github/workflows/ci.yml` により、`lint-and-test` ジョブ（外部の再利用ワークフロー）と `image` ジョブ（`docker build .`）が実行される。`Dockerfile` のビルド工程では `npm test`、`npm run typecheck`、`npm run build` が順に実行される。
