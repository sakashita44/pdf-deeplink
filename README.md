# pdf-deeplink

`pdf-deeplink` は、Zotero 互換 API から取得した PDF について、ページ上の文章や矩形の範囲を指すリンクを発行し、リンクから該当箇所を開いて強調表示する Web アプリケーションである。

発行したリンクには対象 PDF のハッシュ値と任意の目印を含められる。リンク発行後に PDF が更新または差し替えられた場合は変更が検知され、目印から該当箇所を探せる。あわせて、書誌情報・ページ番号・目印を組み合わせた出典文字列をコピーできる。リンクを発行する PDF を開くための補助画面として、PDF が添付されている文献を検索できる一覧画面を備える。

目的に応じた参照先:

- 自分の環境に配置して起動する: [配置](#配置)
- リンクを発行・閲覧する、または画面の警告・エラーを確認する: [使い方](#使い方)
- 開発環境を構築して変更や検査を実行する: [開発](#開発)
- 別のプログラムでリンクを生成・解釈するとき、またはクエリ形式と座標系の規則を確認するとき: [リンクの形式](docs/link-format.md)

## 配置

### 取得元 API の要件

`pdf-deeplink` は、Zotero API v3 と互換性のある HTTP API、および添付キーから PDF ファイルを返すエンドポイントを取得元として要求する。

- 接続方式: `http://<ホスト>[:<ポート>]`（パスは `/` のみ）または Unix ドメインソケット（`unix:<パス>`）。HTTPS での直接接続には対応していないため、HTTPS の取得元へ接続する場合は、手前で TLS を終端するプロキシを経由して HTTP または Unix ドメインソケットで接続すること。
- 共通リクエスト: サーバはすべてのリクエストを `GET` で送信し、`Zotero-API-Version: 3` ヘッダを付与する。認証ヘッダ（API キーやトークン）は送信されないため、認証が必要な取得元へ接続する場合はプロキシ側で付与すること。

取得元が提供する必要があるエンドポイントを次の表に示す。`<apiPath>` は環境変数 `PDF_DEEPLINK_ZOTERO_API_PATH`、`<filePath>` は `PDF_DEEPLINK_ZOTERO_FILE_PATH` で指定する。

| 用途               | リクエスト                                                                                                                                                                                                                                                                           | 求める応答                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文献一覧の取得     | `GET <apiPath>/items/top?start=<開始位置>&limit=100&sort=<項目>&direction=<並び順>`（検索時は `q=<検索語>` が付与される。`sort` は `dateModified`、`dateAdded`、`title`、`creator`、`date` のいずれか、`direction` は `asc` または `desc`）。100 件ずつ先頭 5,000 件までが走査される | HTTP 200 の JSON 配列（Zotero API v3 形式）。総件数を示す `Total-Results` ヘッダを返すと走査回数を抑えられる（省略時は応答件数が 100 件未満になるまで順に取得される）。PDF 添付の有無は、アイテム自身が `data.itemType: "attachment"` かつ `data.contentType: "application/pdf"` であるか、`links.attachment.attachmentType: "application/pdf"` かつ `links.attachment.href` が `/items/<8 文字の英大文字・数字>` で終わるかで判定される |
| 書誌情報の取得     | `GET <apiPath>/items/<8 文字の英大文字・数字>`（添付アイテムに `data.parentItem` がある場合は親アイテムも同じ形式で取得される）                                                                                                                                                      | HTTP 200 の JSON オブジェクト（該当なしは HTTP 404）。添付アイテムは `data.itemType: "attachment"` かつ `data.contentType: "application/pdf"` であること。表示と出典には `data.title`、`data.creators`、`data.date`、`data.publicationTitle`、`data.DOI` が用いられる                                                                                                                                                                    |
| PDF ファイルの取得 | 事前に `GET <apiPath>/items/<8 文字の英大文字・数字>` で PDF 添付であることが確認されたうえで、`GET <filePath の {key} を 8 文字の添付キーへ置換したパス>` が送信される                                                                                                              | HTTP 200 の PDF バイト列（該当なしは HTTP 404）。`Content-Length` ヘッダがある場合はクライアントへの応答へ引き継がれる。PDF 以外の添付アイテムは取得できず、サーバは HTTP 404 を返す                                                                                                                                                                                                                                                     |

### 環境変数

サーバの動作は環境変数で設定する。`PDF_DEEPLINK_ZOTERO_FILE_PATH` を指定しない場合、または `{key}` を含まない場合は起動に失敗する。

| 環境変数                         | 必須 | 既定値                   | 内容・指定形式                                                                                                                                                                                                                               |
| -------------------------------- | ---- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PDF_DEEPLINK_ZOTERO_FILE_PATH`  | 必須 | なし                     | PDF ファイルを取得するパスのテンプレート。`{key}` を必ず含む（例: `/api/users/0/items/{key}/file`）。実行時に `{key}` が 8 文字の添付キーへ置換される                                                                                        |
| `PDF_DEEPLINK_LISTEN`            | 任意 | `127.0.0.1:8787`         | サーバの待ち受け先。`<ホスト>:<ポート>` または Unix ドメインソケット `unix:<パス>` を指定する。Unix ドメインソケットを指定した場合は、起動時に既存の同名ファイルが削除され、パーミッション `0660` で作成される                               |
| `PDF_DEEPLINK_ALLOWED_HOSTS`     | 任意 | `localhost,127.0.0.1`    | 受け付ける HTTP リクエストの `Host` ヘッダ（ポート番号を除くホスト名、大文字小文字を区別しない）をカンマ区切りで指定する。指定すると既定値は置き換わるため、ローカルからの接続も残す場合は `localhost` や `127.0.0.1` もあわせて指定すること |
| `PDF_DEEPLINK_ZOTERO_ENDPOINT`   | 任意 | `http://127.0.0.1:23119` | 取得元 API の接続先。`http://<ホスト>[:<ポート>]`（パスは `/` のみ）または `unix:<パス>` を指定する                                                                                                                                          |
| `PDF_DEEPLINK_ZOTERO_API_PATH`   | 任意 | `/api/users/0`           | 取得元 API のベースパス（末尾の `/` は取り除かれる）                                                                                                                                                                                         |
| `PDF_DEEPLINK_ZOTERO_TIMEOUT_MS` | 任意 | `30000`                  | 取得元への各リクエストのタイムアウト（ミリ秒、正の整数）。超過した場合は HTTP 504 が返される                                                                                                                                                 |
| `PDF_DEEPLINK_STATIC_DIR`        | 任意 | `dist/`                  | ビルド済みフロントエンド資産の配置ディレクトリ。`index.html` が存在しない場合は静的ファイルが配信されず、API（`/app/` 配下）だけが応答する                                                                                                   |

### アクセス制限

`pdf-deeplink` 自身は利用者認証やアクセス認可を行わない。サーバへ到達できる利用者は、取得元の全 PDF と書誌情報にアクセスできる。既定ではループバック（`127.0.0.1:8787`）でのみ待ち受けるため、他端末やネットワーク経由で利用する場合は、前段に認証・アクセス制御を担うリバースプロキシや閉域ネットワークを配置すること。

サーバはリクエストごとに次の制限を適用する。

- `Host` ヘッダの制限: `PDF_DEEPLINK_ALLOWED_HOSTS` に含まれないホスト名へのリクエストは HTTP 403 で拒否される。リバースプロキシ経由や別のホスト名で公開する場合は、利用するホスト名を `PDF_DEEPLINK_ALLOWED_HOSTS` へ指定し（既定値は置き換わるため必要なホスト名をすべて列挙する）、プロキシからその `Host` ヘッダを転送すること。
- クロスサイトリクエストの制限: `Sec-Fetch-Site` ヘッダが付いたリクエストを対象に検査が行われ、`same-origin` と `none` 以外は HTTP 403 で拒否される。ただし、他サイトのリンクから画面を開く通常のページ遷移（`/app/` 配下以外の画面への遷移）は受け付けられ、API（`/app/` 配下）だけが同一オリジンに制限される。
- iframe への埋め込み禁止: 画面の応答には `Content-Security-Policy: frame-ancestors 'none'` が付与されるため、画面を iframe に埋め込めない。
- HTTP メソッドの制限: `GET` 以外のリクエストは HTTP 405 で拒否される。

### 起動手順

コマンド例はいずれも POSIX シェルの構文で記述している。取得元の接続先が既定値（`http://127.0.0.1:23119`）と異なる場合は `PDF_DEEPLINK_ZOTERO_ENDPOINT` を、API のベースパスが既定値（`/api/users/0`）と異なる場合は `PDF_DEEPLINK_ZOTERO_API_PATH` もあわせて指定すること。環境変数の不足や形式の誤りで起動に失敗した場合は、標準エラー出力の内容に従って設定を修正し、再度起動する。

#### コンテナでの起動

開始条件: リポジトリのルートで作業すること。Docker 互換のコンテナランタイムが利用でき、コンテナ内から取得元 API へ到達できること。

注意: コンテナ内では `127.0.0.1` がコンテナ自身を指す。取得元がホストのループバックで待ち受けている場合はコンテナから届かないため、コンテナランタイムが用意するホスト名やマウントした Unix ドメインソケットなど、コンテナ内から到達できる接続先を `PDF_DEEPLINK_ZOTERO_ENDPOINT` に指定する。ホスト側へポートを公開する場合は `PDF_DEEPLINK_LISTEN` に `0.0.0.0:8787` を指定する。コンテナ内のプロセスは非 root ユーザー（`node`）で実行されるため、Unix ドメインソケットを共有する場合はパーミッションを合わせておくこと。

1. `Dockerfile` からイメージをビルドする。ビルド過程でテスト、型検査、フロントエンドのビルドが実行される。

    ```bash
    docker build -t pdf-deeplink .
    ```

1. 環境変数を指定してコンテナを起動する（説明用のコマンド例。`<取得元のホスト>`、`<ポート>`、および `PDF_DEEPLINK_ZOTERO_FILE_PATH` の値は環境に合わせて置き換える。API のベースパスが既定値と異なる場合は `-e PDF_DEEPLINK_ZOTERO_API_PATH=<ベースパス>` も追加する）。

    ```bash
    docker run --rm -p 127.0.0.1:8787:8787 \
        -e PDF_DEEPLINK_LISTEN=0.0.0.0:8787 \
        -e PDF_DEEPLINK_ZOTERO_ENDPOINT=http://<取得元のホスト>:<ポート> \
        -e PDF_DEEPLINK_ZOTERO_FILE_PATH=/api/users/0/items/{key}/file \
        pdf-deeplink
    ```

確認方法:

- TCP で待ち受ける場合: 標準出力に `listening on http://0.0.0.0:8787`（`PDF_DEEPLINK_LISTEN` を変更した場合は指定した `<ホスト>:<ポート>`）と出力され、ブラウザで公開先の URL（この例では `http://127.0.0.1:8787/`）を開いて一覧画面が表示されることを確認する。
- Unix ドメインソケットで待ち受ける場合: 標準出力に `listening on unix:<パス>` と出力され、共有ディレクトリ上にソケットファイルが作成されたこと、および前段のリバースプロキシ経由で一覧画面が表示されることを確認する。

#### Node.js での起動

開始条件: リポジトリのルートで作業すること。Node.js 24 以上が利用でき、取得元 API へ到達できること。

1. 依存パッケージをインストールする。

    ```bash
    npm ci
    ```

1. フロントエンドをビルドし、`dist/` へ出力する。

    ```bash
    npm run build
    ```

1. 環境変数を指定してサーバを起動する（説明用のコマンド例。`PDF_DEEPLINK_ZOTERO_FILE_PATH` の値は取得元の仕様に合わせて置き換える。取得元が既定値と異なる場合は `PDF_DEEPLINK_ZOTERO_ENDPOINT` と、必要であれば `PDF_DEEPLINK_ZOTERO_API_PATH` もあわせて指定する）。

    ```bash
    PDF_DEEPLINK_ZOTERO_FILE_PATH=/api/users/0/items/{key}/file node server/main.ts
    ```

確認方法:

- TCP で待ち受ける場合: 標準出力に `listening on http://127.0.0.1:8787`（`PDF_DEEPLINK_LISTEN` を変更した場合は指定した `<ホスト>:<ポート>`）と出力され、ブラウザで待ち受け先（既定では `http://127.0.0.1:8787/`）を開いて一覧画面が表示されることを確認する。
- Unix ドメインソケットで待ち受ける場合: 標準出力に `listening on unix:<パス>` と出力され、指定パスにソケットファイルが作成されたこと、および前段のリバースプロキシ経由で一覧画面が表示されることを確認する。

## 使い方

### 箇所リンクの発行

1. 対象の PDF をビューア画面で開く。一覧画面（`/`）は、リンクを発行する PDF を開くための補助画面であり、取得元の先頭 5,000 件までを走査して PDF が添付されている文献だけを表示する。検索欄、並び順、表示件数、ページ送りで目的の文献を探し、タイトルを選択する。添付キーが分かっている場合は `/view?src=zotero:<8 文字の添付キー>` を直接開くこともできる。
1. ツールバーで「文章」（既定）または「範囲」ボタンを選び、リンクの対象箇所を指定する。
    - 「文章」: 本文のテキストをドラッグして選択する。複数の行、段組、複数のページにまたがって選択できる。選択を終えるとダイアログが表示され、選択範囲の最初のページにある文章（最大 100 文字）が「目印」欄へ自動で入力される。
    - 「範囲」: ページ上をドラッグして矩形を指定する。図表や、テキストを選択できない箇所の指定に用いる。矩形は 1 ページ内で指定し、ドラッグを終えるとダイアログが表示されて「目印」欄へフォーカスが移る。
1. 必要に応じて「目印」欄（最大 200 文字）へ引用文、図表番号、メモを入力または編集する。目印はリンクと出典に含まれ、PDF が後から更新されたときの検索語として利用される。
1. ダイアログの「リンクをコピー」ボタンを押す。オリジンを含む該当箇所の URL（`<オリジン>/view?...`）がクリップボードへコピーされる。ブラウザがクリップボードへの書き込みを許可しない場合は、手動コピー用のダイアログが表示される。

選択した箇所の矩形数が上限（64 個）を超える場合はリンクを発行できない。その場合は選択範囲を狭めて選び直す。

ビューア画面から一覧画面へ戻る場合は、ツールバーの「一覧」を選択する。

### リンクからの表示

発行された `/view?...` のリンクを開くと、対象の PDF がページ幅に合わせて表示され、リンクが指す最初のページの該当箇所へ自動でスクロールされる。

リンクが指す矩形（複数ページにまたがる場合を含む）は 8 秒間強調表示されたのちに自動で消える。強調表示中に拡大率を変更してページが再描画されても、残り時間の間は強調表示が維持される。

PDF にページラベル（ローマ数字や前付けの番号）が定義されている場合は、ツールバーのページ表示と出典にそのページラベルが用いられる。

#### PDF 変更時の動作

リンクには、発行時点の PDF の SHA-256 ハッシュの先頭 16 桁が記録される。リンクを開くたびにブラウザ側で PDF の SHA-256 が計算されて照合され、更新や差し替えが検知される。

ビューア画面は、リンクが指すページが PDF に存在するかどうかと、SHA-256 の照合結果に応じて次のように動作する。

- リンクが指すページが PDF に存在しない場合（複数ページのリンクでは、最後のページが PDF のページ数を超えるとき）: ページ移動と強調表示は行われず、画面上部に警告バナーと「作成時の箇所」が表示される。
- リンクが指すページがすべて PDF に存在し、SHA-256 が一致しない場合（PDF が更新または差し替えられているとき）: 記録された座標へ移動して強調表示が行われたうえで、画面上部に警告バナーと「作成時の箇所」、リンクが指す最初のページへ移動する「作成時のページへ移動」ボタンが表示される。

リンクに目印が含まれている場合は、いずれのバナーにも「目印で検索」ボタンが表示され、押すたびに文書内の次の一致箇所へ移動する。表示されたバナーは右端の「×」ボタンで閉じられる。

### 出典のコピー

ビューア画面では、リンク発行時とリンク閲覧時のそれぞれで出典文字列をクリップボードへコピーできる。

- リンク発行時: 範囲の選択後に表示されるダイアログで「出典をコピー」ボタンを押すと、選択中の箇所と入力した目印に対する出典がコピーされる。
- リンク閲覧時: 有効な箇所リンクを開いているときにツールバーへ表示される「出典をコピー」ボタンを押すと、リンクが指す箇所と目印に対する出典がコピーされる。

出典文字列は、取得元から得られた書誌情報のうち値がある項目と、対象ページ・目印を、ピリオドと半角空白で区切って連結した形式で出力される。項目の並び順は次のとおり。

- 著者と発行年（`<著者> (<発行年>)`。著者が 3 名以上の場合は先頭の著者に「 ほか」が付く）
- タイトル
- 掲載誌名
- DOI の URL（`https://doi.org/<DOI>`）
- ページ番号（単一ページは `p.<ページ>`、複数ページは `p.<開始>–<終了>`）
- 目印（設定されている場合は `「<目印>」`）

出力例:

```text
Yamada, Sato (2024). Sample Paper. Journal of Examples. https://doi.org/10.1000/example. p.3–4. 「図2」
```

### 画面の警告・エラー一覧

対処欄が「—」の項目には、画面上で取るべき固有の操作はない。

| 画面         | 表示される文言                                                                                                                          | 利用者の対処                                                                                                                                |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| ビューア画面 | `リンクから文献を特定できませんでした。`                                                                                                | リンクの URL（特に `src` パラメータ）が途中で切れていないか確認する。あるいは一覧画面から対象の文献を開き直す                               |
| ビューア画面 | `リンクの一部が正しくないため、該当箇所を表示できません。文書の先頭を表示しています。`                                                  | リンクの URL が欠落・破損していないか確認する。必要であれば該当箇所を選択し直してリンクを再発行する                                         |
| ビューア画面 | `リンクが指す PDF が見つかりません。文献や PDF が削除されたか、別の PDF に差し替えられた可能性があります。`                             | 取得元で文献と添付 PDF の有無を確認する。別の PDF へ差し替えられている場合は一覧画面から開き直し、リンクを再発行する                        |
| ビューア画面 | `PDF を読み込めませんでした（HTTP <状態コード>）。`                                                                                     | —                                                                                                                                           |
| ビューア画面 | `PDF を表示できませんでした。`                                                                                                          | —                                                                                                                                           |
| ビューア画面 | `この PDF はリンクの作成後に更新されています。強調表示の位置がずれている場合は、「目印で検索」で該当箇所を探してください。`             | 強調表示の位置を確認し、ずれている場合はバナーの「目印で検索」から該当箇所を探す。必要であれば更新後の PDF でリンクを再発行する             |

## 開発

### 初期設定

開始条件: リポジトリのルートで POSIX シェルから実行すること。必要なツールは Node.js（バージョンは `.nvmrc` と `mise.toml` に定義）、および Git フックを導入する場合の `uv`。

初期セットアップスクリプトを実行すると、依存パッケージのインストール、`uv` による `pre-commit` の導入、および `pre-commit` / `pre-push` フックの登録が順に実行される。

```bash
bash scripts/setup.sh
```

Git フックを導入せずに依存パッケージだけをインストールする場合は `npm install` を実行する。

### 開発サーバの起動

開始条件: リポジトリのルートで作業し、依存パッケージがインストール済みで、取得元 API へ到達できること。コマンド例は POSIX シェルの構文で記述している。

開発時は API サーバとフロントエンド開発サーバ（Vite）を別々の端末で起動する。Vite は `127.0.0.1:5173` で待ち受け、`/app` へのリクエストを `http://<PDF_DEEPLINK_LISTEN>`（未設定時は `http://127.0.0.1:8787`）へ転送する。

注意:

- Vite の転送先は HTTP を前提とするため、開発サーバ利用時の `PDF_DEEPLINK_LISTEN` には `<ホスト>:<ポート>` 形式を指定すること（Unix ドメインソケットは利用できない）。
- `PDF_DEEPLINK_LISTEN` を既定値から変更する場合は、API サーバと Vite の両方の端末に同じ値を指定すること。
- 取得元が既定値と異なる場合は、API サーバの起動時に `PDF_DEEPLINK_ZOTERO_ENDPOINT`（必要であれば `PDF_DEEPLINK_ZOTERO_API_PATH`）もあわせて指定すること。

1. 1 つ目の端末で API サーバをファイル監視モードで起動する（説明用のコマンド例。`PDF_DEEPLINK_ZOTERO_FILE_PATH` の値は取得元の仕様に合わせて置き換える）。

    ```bash
    PDF_DEEPLINK_ZOTERO_FILE_PATH=/api/users/0/items/{key}/file npm run dev:server
    ```

1. 2 つ目の端末でフロントエンド開発サーバを起動する（`PDF_DEEPLINK_LISTEN` を変更している場合は、この端末でも同じ値を指定する）。

    ```bash
    npm run dev:web
    ```

確認方法: API サーバの端末に `listening on http://127.0.0.1:8787`（`PDF_DEEPLINK_LISTEN` を変更した場合は指定した `<ホスト>:<ポート>`）、Vite の端末に `Local: http://127.0.0.1:5173/` と出力される。ブラウザで `http://127.0.0.1:5173/` を開き、一覧画面が表示されることを確認する。

### 開発用コマンド

#### 検査

ファイルを変更せずに検証だけを実行する。

| コマンド               | 内容                                                                                                                  |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `npm test`             | `node --test` でテストを実行する（`spec/link-vectors.json` と `spec/geometry-vectors.json` を用いた仕様テストを含む） |
| `npm run typecheck`    | TypeScript の型検査を実行する                                                                                         |
| `npm run lint`         | ESLint で静的検査を実行する                                                                                           |
| `npm run format:check` | Prettier で TypeScript ファイルの書式を検査する                                                                       |

#### 整形・ビルド

ソースファイルの書き換えやビルド成果物の出力を伴う。

| コマンド         | 内容                                                                                           |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| `npm run format` | Prettier による TypeScript ファイルの整形と ESLint の自動修正を実行する                        |
| `npm run build`  | Vite でフロントエンドを `dist/` へビルドする（PDF.js の付属資産も `dist/pdfjs/` へ複製される） |

### 自動検査

- Git フック（[`.pre-commit-config.yaml`](.pre-commit-config.yaml)）: コミット時（`pre-commit`）にシークレット混入検査、整形、静的検査、ファイル形式の検査が実行され、プッシュ時（`pre-push`）に型検査とテストが実行される。コミット時の自動整形でファイルが書き換わった場合は、差分を確認して再度ステージする。
- CI（[`.github/workflows/ci.yml`](.github/workflows/ci.yml)）: `main` ブランチ宛ての Pull Request を対象に、Node.js 向けの検査（外部の再利用ワークフロー）と `Dockerfile` によるコンテナイメージのビルドが自動実行される。
