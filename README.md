# pdf-deeplink

Zotero 互換 API から取得した PDF について、ページ上の文章や矩形の範囲を指すリンクを発行し、リンクから該当箇所を開いて強調表示する Web アプリケーション。

- サーバを導入して起動する: [導入](#導入)
- リンクを発行・閲覧する、または画面の警告・エラーを確認する: [使い方](#使い方)
- 開発環境を構築し、変更や検査を実行する: [開発](#開発)
- 別のプログラムでリンクを生成・解釈する、またはクエリ形式と座標系の規則を確認する: [リンクの形式](docs/link-format.md)

## 機能

- PDF 上で文章を選択するか、範囲をドラッグで囲むと、その位置を指すリンクを発行できる。リンクを開くと、該当箇所へ移動して強調表示される。
- 発行したリンクは PDF 内の特定の位置と 1 対 1 で対応するため、該当箇所の共有や、AI による根拠の位置の提示に利用できる。
- リンクには発行時点の PDF のハッシュ値と任意の検索用テキストが含まれる。ハッシュ値の照合により PDF の更新や差し替えを検知でき、変更後も検索用テキストで該当箇所を探せる。
- 書誌情報、ページ番号、検索用テキストを組み合わせた出典文字列をコピーできるため、リンクを開けない場面でも位置を伝えられる。

## 導入

### 取得元 API の要件

`pdf-deeplink` は、文献一覧・書誌情報の取得元（`PDF_DEEPLINK_ZOTERO_ENDPOINT` と `PDF_DEEPLINK_ZOTERO_API_PATH`）と、PDF 本体の取得方法（`PDF_DEEPLINK_ZOTERO_FILE_SOURCE`）を独立して設定する。一覧と書誌の取得には Zotero API v3 と互換性のある API を用い、PDF 本体の取得方法は利用形態に応じて `local`、`web`、`webdav`、`template` のいずれかを選ぶ。

取得元 API への接続とリクエストの共通仕様は次のとおり。

- 接続方式: `http://<ホスト>[:<ポート>]`、`https://<ホスト>[:<ポート>]`（パスは `/` のみ）、または Unix ドメインソケット（`unix:<パス>`）。
- 共通リクエスト: すべてのリクエストを `GET` で送信し、`Zotero-API-Version: 3` ヘッダを付与する。`PDF_DEEPLINK_ZOTERO_API_KEY` または `PDF_DEEPLINK_ZOTERO_API_KEY_FILE` を設定した場合は `Zotero-API-Key` ヘッダも付与する。
- 私設の認証局の証明書: Web API や WebDAV サーバが私設の認証局による TLS 証明書を用いる場合は、Node.js の環境変数 `NODE_EXTRA_CA_CERTS` で認証局の証明書を追加できる（サーバ自身の機能ではない）。

#### 利用形態ごとの組み合わせ

一覧・書誌の取得元は `PDF_DEEPLINK_ZOTERO_ENDPOINT` と `PDF_DEEPLINK_ZOTERO_API_PATH` で指定する。

| 利用形態                                | `PDF_DEEPLINK_ZOTERO_FILE_SOURCE` | 一覧・書誌の取得元                                 | 取得方法に必須の環境変数         |
| --------------------------------------- | --------------------------------- | -------------------------------------------------- | -------------------------------- |
| ローカルの Zotero（Local API）          | `local`                           | 既定値（`http://127.0.0.1:23119`、`/api/users/0`） | `PDF_DEEPLINK_ZOTERO_LOCAL_DIRS` |
| zotero.org の Web API（Zotero Storage） | `web`                             | Web API の接続先とライブラリパスを指定             | なし                             |
| WebDAV でファイルを同期                 | `webdav`                          | Web API など Zotero API v3 互換 API を指定         | `PDF_DEEPLINK_ZOTERO_WEBDAV_URL` |
| PDF を直接返す HTTP の経路              | `template`                        | Zotero API v3 互換 API を指定                      | `PDF_DEEPLINK_ZOTERO_FILE_PATH`  |

取得元 API に認証が必要な場合は、利用形態にかかわらず `PDF_DEEPLINK_ZOTERO_API_KEY`（または `PDF_DEEPLINK_ZOTERO_API_KEY_FILE`）を指定する。WebDAV サーバに認証が必要な場合は、`PDF_DEEPLINK_ZOTERO_WEBDAV_USERNAME` と `PDF_DEEPLINK_ZOTERO_WEBDAV_PASSWORD`（または `PDF_DEEPLINK_ZOTERO_WEBDAV_PASSWORD_FILE`）をあわせて指定する。

#### 取得元 API のエンドポイント

一覧・書誌の取得と PDF 取得前の確認に用いるエンドポイントを次の表に示す。`<apiPath>` は環境変数 `PDF_DEEPLINK_ZOTERO_API_PATH`（末尾の `/` を除いた値）を表す。

| 用途               | リクエスト                                                                                                                                           | 求める応答                                                                                                                                               |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文献一覧の取得     | `GET <apiPath>/items/top?start=<開始位置>&limit=100&sort=<項目>&direction=<並び順>`（検索時は `q=<検索語>` を付与）。100 件ずつ先頭 5,000 件まで走査 | HTTP 200 の JSON 配列（Zotero API v3 形式）。総件数を示す `Total-Results` ヘッダを返すと走査回数を抑えられる                                             |
| 書誌情報の取得     | `GET <apiPath>/items/<8 文字の英大文字・数字>`（`data.parentItem` がある場合は親アイテムも取得）                                                     | HTTP 200 の JSON オブジェクト（該当なしは HTTP 404）。添付アイテムは `data.itemType: "attachment"` かつ `data.contentType: "application/pdf"` であること |
| PDF ファイルの取得 | 事前に `GET <apiPath>/items/<8 文字の英大文字・数字>` で PDF 添付を確認したうえで、`PDF_DEEPLINK_ZOTERO_FILE_SOURCE` に応じて取得                    | 取得方法ごとの応答（「PDF の取得方法ごとの動作」を参照）                                                                                                 |

- 文献一覧の `sort` には `dateModified`、`dateAdded`、`title`、`creator`、`date` のいずれか、`direction` には `asc` または `desc` が指定される。`Total-Results` ヘッダが省略された場合は、応答件数が 100 件未満になるまで順に取得される。
- 表示と出典には `data.title`、`data.creators`、`data.date`、`data.publicationTitle`、`data.DOI` が用いられる。

#### PDF の取得方法ごとの動作

##### `local`

ローカルの Zotero の Local API が返す `file:` URL から、サーバと同一ファイルシステム上の PDF ファイルを直接開く。Zotero が返すパスをそのまま開き、パスの書き換えには対応しないため、Zotero と同じパスでファイルを参照できる環境でのみ利用できる（コンテナ内から異なるパスで参照する構成では利用できない）。

- 取得元 API へ `GET <apiPath>/items/<8 文字の添付キー>/file` を送信し、HTTP 302 とローカルの `file:` URL を指す `Location` ヘッダを受け付ける。
- シンボリックリンク解決後の実パスが `PDF_DEEPLINK_ZOTERO_LOCAL_DIRS` の配下にある通常ファイルだけを開く。許可ディレクトリの外にあるパス、ネットワーク上のパス、通常ファイル以外の対象は開かない。

##### `web`

Zotero Web API など、HTTP 200 または HTTPS のリダイレクトで PDF 本体を返す経路から取得する。zotero.org にファイルを保存せず WebDAV で同期しているライブラリでは Web API の `items/<キー>/file` が HTTP 404 を返すため、`webdav` を選択する。

- 取得元 API へ `GET <apiPath>/items/<8 文字の添付キー>/file` を送信し、HTTP 200 の PDF バイト列、または `https://` で始まる絶対 URL へのリダイレクトを受け付ける。
- HTTPS でないリダイレクト先には従わない。リダイレクト先へは `Zotero-API-Key` ヘッダを送信しない。

##### `webdav`

Zotero の WebDAV 同期先に配置された ZIP アーカイブから PDF 本体を展開して取得する。Zotero の WebDAV 同期では、設定画面に入力する URL の配下の `zotero/` に `<キー>.zip` が配置される。

- `PDF_DEEPLINK_ZOTERO_WEBDAV_URL` 配下の `GET <ベースパス>/zotero/<8 文字の添付キー>.zip` を WebDAV サーバへ送信し、HTTP 200 の ZIP アーカイブから PDF を展開する。
- 認証は HTTP Basic 認証にのみ対応する（Digest 認証などの他の方式には対応しない）。
- アーカイブと展開後のファイルはそれぞれ 512 MiB を上限とする。

##### `template`

取得元 API と同一の接続先（`PDF_DEEPLINK_ZOTERO_ENDPOINT`）上の任意パスから、PDF バイト列を直接取得する。`PDF_DEEPLINK_ZOTERO_FILE_PATH` の `{key}` を 8 文字の添付キーへ置換したパスへ `GET` を送信し、HTTP 200 の PDF バイト列を受け付ける。

#### エラー時の応答

取得元との通信や PDF の取得でエラーが起きた場合、サーバはクライアントへ次の状態コードを返す。HTTP 502 や HTTP 504 では、原因がサーバの標準エラー出力へ出力される。

- HTTP 404: 対象の文献、添付 PDF、またはローカル・WebDAV 上のファイルが見つからない（PDF 添付以外のアイテムを指定した場合を含む）。取得元での文献と添付 PDF の有無や同期状態を確認する。
- HTTP 504: 取得元 API、リダイレクト先、または WebDAV サーバへのリクエストが `PDF_DEEPLINK_ZOTERO_TIMEOUT_MS` を超えてタイムアウトした。取得元の応答状況やネットワーク経路を確認し、必要に応じて `PDF_DEEPLINK_ZOTERO_TIMEOUT_MS` を調整する。
- HTTP 502: 取得元へ到達できない、または取得元や PDF 取得処理でその他のエラー（想定外の応答、許可ディレクトリ外のパス、不正なリダイレクト、展開できない ZIP など）が起きた。サーバの標準エラー出力で原因を確認し、接続先、認証情報、TLS 証明書、許可ディレクトリ、取得方法の設定を見直す。

### 環境変数

サーバの動作は環境変数で設定する。PDF 本体の取得方法は `PDF_DEEPLINK_ZOTERO_FILE_SOURCE` で指定する（省略しても `PDF_DEEPLINK_ZOTERO_FILE_PATH` を指定していれば `template` が選ばれる）。必須の変数が不足している場合、選択した取得方法以外の固有変数（表の必須欄に取得方法名が記載された変数）を指定した場合、または値の形式に誤りがある場合は、サーバは起動に失敗する。

資格情報（`PDF_DEEPLINK_ZOTERO_API_KEY` と `PDF_DEEPLINK_ZOTERO_WEBDAV_PASSWORD`）は、環境変数へ直接渡すか、値のファイルを末尾に `_FILE` が付いた対応変数で指定する。両方同時に指定すると起動に失敗する。ファイルは UTF-8 で読み込まれ、末尾の改行 1 つ（および先頭の BOM）だけが取り除かれる。前後の空白は取り除かれず、空の値や改行を含む値を指定すると起動に失敗する。

| 環境変数                                   | 必須                                                   | 既定値                   | 内容・指定形式                                                                                                                                                                                                                               |
| ------------------------------------------ | ------------------------------------------------------ | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PDF_DEEPLINK_ZOTERO_FILE_SOURCE`          | 必須（`PDF_DEEPLINK_ZOTERO_FILE_PATH` 指定時は省略可） | なし                     | PDF 本体の取得方法（`local`、`web`、`webdav`、`template`）                                                                                                                                                                                   |
| `PDF_DEEPLINK_ZOTERO_LOCAL_DIRS`           | `local` 時必須                                         | なし                     | `local` で読み込みを許可するディレクトリの絶対パス。環境変数 `PATH` と同じ区切り文字（POSIX は `:`、Windows は `;`）で複数指定可。存在しないパスやファイルは起動時にエラーになる                                                             |
| `PDF_DEEPLINK_ZOTERO_WEBDAV_URL`           | `webdav` 時必須                                        | なし                     | WebDAV 同期先のベース URL（`http://` または `https://`。資格情報・クエリ・フラグメント不可）。配下の `zotero/<8 文字の添付キー>.zip` を要求する                                                                                              |
| `PDF_DEEPLINK_ZOTERO_WEBDAV_USERNAME`      | 任意（`webdav` 固有）                                  | なし                     | WebDAV の Basic 認証ユーザー名（空文字と `:` は不可）。パスワードと組で指定する                                                                                                                                                              |
| `PDF_DEEPLINK_ZOTERO_WEBDAV_PASSWORD`      | 任意（`webdav` 固有）                                  | なし                     | WebDAV の Basic 認証パスワード。ユーザー名と組で指定する                                                                                                                                                                                     |
| `PDF_DEEPLINK_ZOTERO_WEBDAV_PASSWORD_FILE` | 任意（`webdav` 固有）                                  | なし                     | `PDF_DEEPLINK_ZOTERO_WEBDAV_PASSWORD` を格納したファイルのパス。ユーザー名と組で指定する                                                                                                                                                     |
| `PDF_DEEPLINK_ZOTERO_FILE_PATH`            | `template` 時必須                                      | なし                     | PDF 取得パスのテンプレート（例: `/api/users/0/items/{key}/file`）。`{key}` を必ず含める                                                                                                                                                      |
| `PDF_DEEPLINK_ZOTERO_ENDPOINT`             | 任意                                                   | `http://127.0.0.1:23119` | 取得元 API の接続先。`http://<ホスト>[:<ポート>]`、`https://<ホスト>[:<ポート>]`（パスは `/` のみ）、または `unix:<パス>`                                                                                                                    |
| `PDF_DEEPLINK_ZOTERO_API_PATH`             | 任意                                                   | `/api/users/0`           | 取得元 API のベースパス（末尾の `/` は取り除かれる）                                                                                                                                                                                         |
| `PDF_DEEPLINK_ZOTERO_API_KEY`              | 任意                                                   | なし                     | 取得元 API へ `Zotero-API-Key` ヘッダで付与する API キー。`web` のリダイレクト先へは送信されない                                                                                                                                             |
| `PDF_DEEPLINK_ZOTERO_API_KEY_FILE`         | 任意                                                   | なし                     | `PDF_DEEPLINK_ZOTERO_API_KEY` を格納したファイルのパス                                                                                                                                                                                       |
| `PDF_DEEPLINK_ZOTERO_TIMEOUT_MS`           | 任意                                                   | `30000`                  | 取得元 API、リダイレクト先、WebDAV サーバへの各リクエストのタイムアウト（ミリ秒、正の整数）。超過時は HTTP 504                                                                                                                               |
| `PDF_DEEPLINK_LISTEN`                      | 任意                                                   | `127.0.0.1:8787`         | サーバの待ち受け先。`<ホスト>:<ポート>` または Unix ドメインソケット `unix:<パス>` を指定する。Unix ドメインソケットでは起動時に既存の同名ファイルが削除され、パーミッション `0660` で作成される                                             |
| `PDF_DEEPLINK_ALLOWED_HOSTS`               | 任意                                                   | `localhost,127.0.0.1`    | 受け付ける HTTP リクエストの `Host` ヘッダ（ポート番号を除くホスト名、大文字小文字を区別しない）をカンマ区切りで指定する。指定すると既定値は置き換わるため、ローカルからの接続も残す場合は `localhost` や `127.0.0.1` もあわせて指定すること |
| `PDF_DEEPLINK_STATIC_DIR`                  | 任意                                                   | `dist/`                  | ビルド済みフロントエンド資産の配置ディレクトリ。`index.html` が存在しない場合は静的ファイルが配信されず、API（`/app/` 配下）だけが応答する                                                                                                   |

### アクセス制限

`pdf-deeplink` 自身は利用者認証やアクセス認可を行わない。サーバへ到達できる利用者は、取得元の全 PDF と書誌情報にアクセスできる。既定ではループバック（`127.0.0.1:8787`）でのみ待ち受けるため、他端末やネットワーク経由で利用する場合は、前段に認証・アクセス制御を担うリバースプロキシや閉域ネットワークを配置すること。

サーバはリクエストごとに次の制限を適用する。

- `Host` ヘッダの制限: `PDF_DEEPLINK_ALLOWED_HOSTS` に含まれないホスト名へのリクエストは HTTP 403 で拒否される。リバースプロキシ経由や別のホスト名で公開する場合は、利用するホスト名を `PDF_DEEPLINK_ALLOWED_HOSTS` へ指定し（既定値は置き換わるため必要なホスト名をすべて列挙する）、プロキシからその `Host` ヘッダを転送すること。
- クロスサイトリクエストの制限: `Sec-Fetch-Site` ヘッダが付いたリクエストを対象に検査が行われ、`same-origin` と `none` 以外は HTTP 403 で拒否される。ただし、他サイトのリンクから画面を開く通常のページ遷移（`/app/` 配下以外への文書遷移）はこの制限の対象外として受け付けられる。
- iframe への埋め込み禁止: 画面の応答には `Content-Security-Policy: frame-ancestors 'none'` が付与されるため、画面を iframe に埋め込めない。
- HTTP メソッドの制限: `GET` 以外のリクエストは HTTP 405 で拒否される。

### 起動手順

コマンド例はいずれも POSIX シェルの構文で記述している。利用形態に応じて `PDF_DEEPLINK_ZOTERO_FILE_SOURCE` と対応する環境変数を指定すること。取得元の接続先が既定値（`http://127.0.0.1:23119`）と異なる場合は `PDF_DEEPLINK_ZOTERO_ENDPOINT`、API のベースパスが既定値（`/api/users/0`）と異なる場合は `PDF_DEEPLINK_ZOTERO_API_PATH`、取得元 API の認証が必要な場合は `PDF_DEEPLINK_ZOTERO_API_KEY` または `PDF_DEEPLINK_ZOTERO_API_KEY_FILE` もあわせて指定すること。環境変数の不足や形式の誤りで起動に失敗した場合は、標準エラー出力の内容に従って設定を修正し、再度起動する。

#### コンテナでの起動

開始条件: リポジトリのルートで作業すること。Docker 互換のコンテナランタイムが利用でき、コンテナ内から取得元 API へ到達できること。

注意: コンテナ内では `127.0.0.1` がコンテナ自身を指す。取得元がホストのループバックで待ち受けている場合はコンテナから届かないため、コンテナランタイムが用意するホスト名やマウントした Unix ドメインソケットなど、コンテナ内から到達できる接続先を `PDF_DEEPLINK_ZOTERO_ENDPOINT` に指定する。ホスト側へポートを公開する場合は `PDF_DEEPLINK_LISTEN` に `0.0.0.0:8787` を指定する。コンテナ内のプロセスは非 root ユーザー（`node`）で実行されるため、Unix ドメインソケットを共有する場合は `node` ユーザーからアクセスできるようパーミッションを設定すること。

1. `Dockerfile` からイメージをビルドする。ビルド過程でテスト、型検査、フロントエンドのビルドが実行される。

    ```bash
    docker build -t pdf-deeplink .
    ```

1. 環境変数を指定してコンテナを起動する（`template` を用いる場合の説明用のコマンド例。利用形態に合わせて環境変数を置き換える。Zotero と同じパスでファイルを参照できないコンテナでは `local` は利用できない）。

    ```bash
    docker run --rm -p 127.0.0.1:8787:8787 \
        -e PDF_DEEPLINK_LISTEN=0.0.0.0:8787 \
        -e PDF_DEEPLINK_ZOTERO_ENDPOINT=http://<取得元のホスト>:<ポート> \
        -e PDF_DEEPLINK_ZOTERO_FILE_SOURCE=template \
        -e PDF_DEEPLINK_ZOTERO_FILE_PATH=/api/users/0/items/{key}/file \
        pdf-deeplink
    ```

確認方法:

- TCP で待ち受ける場合: 標準出力に `listening on http://0.0.0.0:8787`（`PDF_DEEPLINK_LISTEN` を変更した場合は指定した `<ホスト>:<ポート>`）と出力され、ブラウザで公開先の URL（この例では `http://127.0.0.1:8787/`）を開いて一覧画面が表示されることを確認する。
- Unix ドメインソケットで待ち受ける場合: 標準出力に `listening on unix:<パス>` と出力され、共有ディレクトリ上にソケットファイルが作成されたこと、および前段のリバースプロキシ経由で一覧画面が表示されることを確認する。

#### Node.js での起動

開始条件: リポジトリのルートで作業すること。Node.js 24 以上が利用でき、取得元 API へ到達できること。

1. 依存パッケージをインストールする。

    ```bash
    npm ci
    ```

1. フロントエンドをビルドし、`dist/` へ出力する。

    ```bash
    npm run build
    ```

1. 環境変数を指定してサーバを起動する（ローカルの Zotero を `local` で参照する場合の説明用のコマンド例。許可ディレクトリには Zotero の `storage` ディレクトリなどを指定し、他の利用形態では環境変数を置き換える）。

    ```bash
    PDF_DEEPLINK_ZOTERO_FILE_SOURCE=local PDF_DEEPLINK_ZOTERO_LOCAL_DIRS=<許可ディレクトリの絶対パス> node server/main.ts
    ```

確認方法:

- TCP で待ち受ける場合: 標準出力に `listening on http://127.0.0.1:8787`（`PDF_DEEPLINK_LISTEN` を変更した場合は指定した `<ホスト>:<ポート>`）と出力され、ブラウザで待ち受け先（既定では `http://127.0.0.1:8787/`）を開いて一覧画面が表示されることを確認する。
- Unix ドメインソケットで待ち受ける場合: 標準出力に `listening on unix:<パス>` と出力され、指定パスにソケットファイルが作成されたこと、および前段のリバースプロキシ経由で一覧画面が表示されることを確認する。

## 使い方

### リンクの発行

1. 対象の PDF をビューア画面で開く。一覧画面（`/`）は取得元の先頭 5,000 件までを走査し、PDF が添付されている文献だけを表示する。検索欄、並び順、表示件数、ページ送りで目的の文献を探し、タイトルを選択する。添付キーが分かっている場合は `/view?src=zotero:<8 文字の添付キー>` を直接開くこともできる。
1. ツールバーで「文章」（既定）または「範囲」ボタンを選び、リンクの対象箇所を指定する。
    - 「文章」: 本文のテキストをドラッグして選択する。複数の行、段組、複数のページにまたがって選択できる。選択を終えるとダイアログが表示され、選択範囲の最初のページにある文章（最大 100 文字）が「検索用テキスト」欄へ自動で入力される。
    - 「範囲」: ページ上をドラッグして矩形を指定する。図表や、テキストを選択できない箇所の指定に用いる。矩形は 1 ページ内で指定し、ドラッグを終えるとダイアログが表示される。
1. 必要に応じて「検索用テキスト」欄（最大 200 文字）を入力または編集する。検索用テキストは、PDF が更新または差し替えられたときの該当箇所の検索と、出典の表記に用いられる。本文の引用や図表のタイトルなど、PDF 内で位置を特定しやすい文字列が適している。
1. ダイアログの「リンクをコピー」ボタンを押す。オリジンを含む該当箇所の URL（`<オリジン>/view?...`）がクリップボードへコピーされる。ブラウザがクリップボードへの書き込みを許可しない場合は、手動コピー用のダイアログが表示される。

選択範囲が広すぎるとリンクを発行できない。その場合は範囲を狭めて選択し直す。

ビューア画面から一覧画面へ戻る場合は、ツールバーの「一覧」を選択する。

### リンクからの表示

発行された `/view?...` のリンクを開くと、対象の PDF がページ幅に合わせて表示され、リンクが指す最初のページの該当箇所へ自動でスクロールされる。

該当箇所（複数ページにまたがる場合を含む）は 8 秒間強調表示されたのちに自動で消える。強調表示中に拡大率を変更してページが再描画されても、残り時間の間は強調表示が維持される。

PDF にページラベル（ローマ数字や前付けの番号）が定義されている場合は、ツールバーのページ表示や出典にそのページラベルが用いられる。

#### PDF 変更時の動作

リンクには、発行時点の PDF の SHA-256 ハッシュの先頭 16 桁が記録される。リンクを開くたびにブラウザ側で PDF の SHA-256 が計算されて照合され、更新や差し替えが検知される。

ビューア画面は、リンクが指すページが PDF に存在するかどうかと、SHA-256 の照合結果に応じて次のように動作する。

- リンクが指すページが PDF に存在しない場合（複数ページのリンクでは、最後のページが PDF のページ数を超えるとき）: ページ移動と強調表示は行われず、画面上部に警告バナーが表示される。
- リンクが指すページがすべて PDF に存在し、SHA-256 が一致しない場合（PDF が更新または差し替えられているとき）: リンクに記録された位置へ移動して強調表示が行われたうえで、画面上部に警告バナーと、リンクが指す最初のページへ移動する「作成時のページへ移動」ボタンが表示される。

いずれの警告バナーにも「作成時の指定位置」（ページ番号、および設定されている場合は検索用テキスト）が表示され、位置を探す手がかりにできる。リンクに検索用テキストが含まれている場合は「一致する箇所を検索」ボタンも表示される。「一致する箇所を検索」ボタンを押すと、検索用テキストと一致する箇所へ移動でき、押すたびに次の一致箇所へ順に移動する。警告バナーは右端の「×」ボタンで閉じられる。

### 出典のコピー

ビューア画面では、リンク発行時とリンク閲覧時のそれぞれで出典文字列をクリップボードへコピーできる。

- リンク発行時: 範囲の選択後に表示されるダイアログで「出典をコピー」ボタンを押すと、選択中の箇所と入力した検索用テキストに対する出典がコピーされる。
- リンク閲覧時: PDF 内の位置を指す有効なリンクを開いているときにツールバーへ表示される「出典をコピー」ボタンを押すと、リンクが指す箇所と検索用テキストに対する出典がコピーされる。

出典文字列は、取得元から得られた書誌情報のうち値がある項目と、対象ページ・検索用テキストを、ピリオドと半角空白で区切って連結した形式で出力される。項目の並び順は次のとおり。

- 著者と発行年（`<著者> (<発行年>)`。著者が 3 名以上の場合は先頭の著者に「 ほか」が付く）
- タイトル
- 掲載誌名
- DOI の URL（`https://doi.org/<DOI>`）
- ページ番号（単一ページは `p.<ページ>`、複数ページは `p.<開始>–<終了>`）
- 検索用テキスト（設定されている場合は `「<検索用テキスト>」`）

出力例:

```text
Yamada, Sato (2024). Sample Paper. Journal of Examples. https://doi.org/10.1000/example. p.3–4. 「図2」
```

## 開発

### 初期設定

開始条件: リポジトリのルートで POSIX シェルから実行すること。必要なツールは Node.js（バージョンは `.nvmrc` と `mise.toml` に定義）、および Git フックを導入する場合の `uv`。

初期セットアップでは次のコマンドを実行する。依存パッケージのインストール、`uv` による `pre-commit` の導入、および `pre-commit` / `pre-push` フックの登録が順に実行される。

```bash
bash scripts/setup.sh
```

Git フックを導入せずに依存パッケージだけをインストールする場合は `npm install` を実行する。

### 開発サーバの起動

開始条件: リポジトリのルートで作業し、依存パッケージがインストール済みで、取得元 API へ到達できること。コマンド例は POSIX シェルの構文で記述している。

開発時は API サーバとフロントエンド開発サーバ（Vite）を別々の端末で起動する。Vite は `127.0.0.1:5173` で待ち受け、`/app` へのリクエストを `http://<PDF_DEEPLINK_LISTEN>`（未設定時は `http://127.0.0.1:8787`）へ転送する。

注意:

- Vite の転送先は HTTP を前提とするため、開発サーバ利用時の `PDF_DEEPLINK_LISTEN` には `<ホスト>:<ポート>` 形式を指定すること（Unix ドメインソケットは利用できない）。
- `PDF_DEEPLINK_LISTEN` を既定値から変更する場合は、API サーバと Vite の両方の端末に同じ値を指定すること。
- 取得元の接続先が既定値と異なる場合は `PDF_DEEPLINK_ZOTERO_ENDPOINT`、API のベースパスが既定値と異なる場合は `PDF_DEEPLINK_ZOTERO_API_PATH`、取得元 API の認証が必要な場合は `PDF_DEEPLINK_ZOTERO_API_KEY` または `PDF_DEEPLINK_ZOTERO_API_KEY_FILE` も、API サーバの起動時にあわせて指定すること。

1. 1 つ目の端末で API サーバをファイル監視モードで起動する（ローカルの Zotero を `local` で参照する場合の説明用のコマンド例。他の利用形態では環境変数を置き換える）。

    ```bash
    PDF_DEEPLINK_ZOTERO_FILE_SOURCE=local PDF_DEEPLINK_ZOTERO_LOCAL_DIRS=<許可ディレクトリの絶対パス> npm run dev:server
    ```

1. 2 つ目の端末でフロントエンド開発サーバを起動する（`PDF_DEEPLINK_LISTEN` を変更している場合は、この端末でも同じ値を指定する）。

    ```bash
    npm run dev:web
    ```

確認方法: API サーバの端末に `listening on http://127.0.0.1:8787`（`PDF_DEEPLINK_LISTEN` を変更した場合は指定した `<ホスト>:<ポート>`）、Vite の端末に `Local: http://127.0.0.1:5173/` と出力される。ブラウザで `http://127.0.0.1:5173/` を開き、一覧画面が表示されることを確認する。

### 開発用コマンド

#### 検査

ファイルを変更せずに検証だけを実行する。

| コマンド               | 内容                                                                                                                  |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `npm test`             | `node --test` でテストを実行する（`spec/link-vectors.json` と `spec/geometry-vectors.json` を用いた仕様テストを含む） |
| `npm run typecheck`    | TypeScript の型検査を実行する                                                                                         |
| `npm run lint`         | ESLint で静的検査を実行する                                                                                           |
| `npm run format:check` | Prettier で TypeScript ファイルの書式を検査する                                                                       |

#### 整形・ビルド

ソースファイルの書き換えやビルド成果物の出力を伴う。

| コマンド         | 内容                                                                                           |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| `npm run format` | Prettier による TypeScript ファイルの整形と ESLint の自動修正を実行する                        |
| `npm run build`  | Vite でフロントエンドを `dist/` へビルドする（PDF.js の付属資産も `dist/pdfjs/` へ複製される） |

### 自動検査

- Git フック（[`.pre-commit-config.yaml`](.pre-commit-config.yaml)）: コミット時（`pre-commit`）にシークレット混入検査、整形、静的検査、ファイル形式の検査が実行され、プッシュ時（`pre-push`）に型検査とテストが実行される。コミット時の自動整形でファイルが書き換わった場合は、差分を確認して再度ステージする。
- CI（[`.github/workflows/ci.yml`](.github/workflows/ci.yml)）: `main` ブランチ宛ての Pull Request を対象に、Node.js 向けの検査（外部の再利用ワークフロー）と `Dockerfile` によるコンテナイメージのビルドが自動実行される。
