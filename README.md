# pdf-deeplink

`pdf-deeplink` は、Zotero 互換 API から取得した PDF について、ページ上の文章や矩形の範囲を指すリンクを発行し、リンクから該当箇所を開いて強調表示する Web アプリケーションである。

発行したリンクには対象 PDF のハッシュ値と任意の目印を含められる。リンク作成後に PDF が更新または差し替えられた場合は変更を検知し、目印から該当箇所を探せる。あわせて、書誌情報・ページ番号・目印を組み合わせた出典文字列をコピーできる。リンクを発行する PDF を選ぶ補助画面として、PDF 添付済みの文献を検索・並び替えできる一覧画面を備える。

リンクのクエリ形式と座標系の詳細は [リンク形式の仕様](docs/link-format.md) を参照のこと。

## 使い方

### 箇所リンクの発行

1. 対象の PDF をビューア画面で開く。トップ画面（`/`）には、取得元にある文献のうち PDF が添付されているものだけが表示される。検索欄（タイトル・著者・年）、並び順、表示件数、ページ送りで目的の文献を探し、タイトルを選択する。添付キーが分かっている場合は `/view?src=zotero:<8文字の添付キー>` を直接開くこともできる。
1. ツールバーの「選択の方法」から `文章`（既定）または `範囲` を選び、リンクの対象箇所を指定する。
    - `文章`: 本文のテキストをドラッグして選択する。複数の行、段組、複数のページにまたがって選択できる。選択を終えると「リンクの作成」ダイアログが開き、先頭ページで選択した文章（最大 100 文字）が「目印」欄へ自動で入力される。
    - `範囲`: ページ上をドラッグして矩形を指定する。図表や、テキストを選択できない箇所の指定に用いる。矩形は 1 ページ内で指定し、ドラッグを終えると「リンクの作成」ダイアログが開いて「目印」欄へフォーカスが移る。
1. 必要に応じて「目印」欄（最大 200 文字）へ引用文、図表番号、メモを入力または編集する。目印はリンクと出典に含まれ、PDF が後から更新されたときの検索語として利用される。
1. 「リンクをコピー」を押す。該当箇所を指す URL（`/view?...`）がクリップボードへコピーされる。ブラウザがクリップボードへの書き込みを許可しない場合は、手動コピー用のダイアログが表示される。

選択した箇所の矩形数が上限（64 個）を超える場合はリンクを作成できない。その場合は選択範囲を狭めて選び直す。ビューア画面から一覧画面へ戻る場合は、ツールバーの「一覧」を選択する。

### リンクからの表示

発行された `/view?...` のリンクを開くと、対象の PDF がページ幅に合わせて表示され、先頭の対象ページにある該当箇所へ自動でスクロールする。

リンクが指す矩形（複数ページにまたがる場合を含む）は 8 秒間強調表示されたのちに自動で消える。強調表示中に拡大率を変更してページが再描画されても、残り時間の間は強調表示が維持される。

PDF にページラベル（ローマ数字や前付けの番号）が定義されている場合は、ツールバーのページ表示と出典にそのページラベルが用いられる。

### PDF 更新時の動作

リンクには、作成時点の PDF の SHA-256 ハッシュの先頭 16 桁が記録される。リンクを開くたびにブラウザ側で PDF の SHA-256 を計算して照合し、更新や差し替えを検知する。

- PDF が更新されている場合（対象ページが存在するとき）: 記録された座標へ移動・強調表示したうえで、画面上部に警告バナーを表示する。バナーには作成時のページと目印（「作成時の箇所」）、作成時の先頭ページへ移動する `p.<ページ> へ移動` ボタンが表示される。リンクに目印が含まれている場合は `目印で検索` ボタンも表示され、押すたびに文書内の次の一致箇所へ移動する。
- リンクが指すページが存在しない場合: ページ移動と強調表示は行わず、画面上部に警告バナーと「作成時の箇所」を表示する。リンクに目印が含まれている場合は `目印で検索` ボタンから該当箇所を探せる。

表示されたバナーは右端の `×` ボタンで閉じられる。

### 出典のコピー

ビューア画面では、リンク発行時とリンク閲覧時のそれぞれで出典文字列をクリップボードへコピーできる。

- リンク発行時: 「リンクの作成」ダイアログの「出典をコピー」を押すと、選択中の箇所と入力した目印に対する出典がコピーされる。
- リンク閲覧時: 有効な箇所リンクを開いているときにツールバーへ表示される「出典をコピー」を押すと、リンクが指す箇所と目印に対する出典がコピーされる。

出典文字列は、取得元から得られた書誌情報のうち値がある項目と、対象ページ・目印を、ピリオドと半角空白で区切って連結した形式で出力される。項目の並び順は次のとおり。

- 著者と発行年（`<著者> (<発行年>)`。著者が 3 名以上の場合は先頭の著者に「 ほか」を付ける）
- タイトル
- 掲載誌名
- DOI の URL（`https://doi.org/<DOI>`）
- ページ番号（単一ページは `p.<ページ>`、複数ページは `p.<開始>–<終了>`）
- 目印（設定されている場合、`「<目印>」`）

出力例を次に示す。

```text
Yamada, Sato (2024). Sample Paper. Journal of Examples. https://doi.org/10.1000/example. p.3–4. 「図2」
```

## 配置

### 取得元 API の要件

`pdf-deeplink` は、Zotero API v3 と互換性のある HTTP API、および添付キーから PDF ファイルを返すエンドポイントを取得元として要求する。

- 接続方式: `http://<ホスト>[:<ポート>]`（パスは `/` のみ）または Unix ドメインソケット（`unix:<パス>`）。HTTPS での直接接続には対応していない。HTTPS の取得元へ接続する場合は、手前で TLS を終端するプロキシを経由して HTTP または Unix ドメインソケットで接続すること。
- 共通リクエスト: すべてのリクエストを `GET` で送信し、`Zotero-API-Version: 3` ヘッダを付与する。認証ヘッダ（API キーやトークン）は送信しない。

取得元が提供する必要があるエンドポイントを次に示す。`<apiPath>` は環境変数 `PDF_DEEPLINK_ZOTERO_API_PATH`、`<filePath>` は `PDF_DEEPLINK_ZOTERO_FILE_PATH` で指定する。

| 用途               | リクエスト                                                                                                                                                                                                                            | 求める応答                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文献一覧の取得     | `GET <apiPath>/items/top?start=<開始位置>&limit=100&sort=<項目>&direction=<並び順>`（検索時は `q=<検索語>` を付与。`sort` は `dateModified`、`dateAdded`、`title`、`creator`、`date` のいずれか、`direction` は `asc` または `desc`） | HTTP 200 の JSON 配列（Zotero API v3 形式）。総件数を示す `Total-Results` ヘッダに対応している（省略時は応答件数が 100 件未満になるまで順に取得する）。PDF 添付の有無は、アイテム自身が `data.itemType: "attachment"` かつ `data.contentType: "application/pdf"` であるか、`links.attachment.attachmentType: "application/pdf"` かつ `links.attachment.href` が `/items/<8文字の英大文字・数字キー>` で終わるかで判定される |
| 書誌情報の取得     | `GET <apiPath>/items/<key>`（`<key>` は 8 文字の英大文字・数字。添付アイテムに `data.parentItem` がある場合は親アイテムも同じ形式で取得する）                                                                                         | HTTP 200 の JSON オブジェクト（該当なしは HTTP 404）。添付アイテムは `data.itemType: "attachment"` かつ `data.contentType: "application/pdf"` であること。表示と出典には `data.title`、`data.creators`、`data.date`、`data.publicationTitle`、`data.DOI` を用いる                                                                                                                                                           |
| PDF ファイルの取得 | `GET <filePath の {key} を 8 文字の添付キーへ置換したパス>`                                                                                                                                                                           | HTTP 200 の PDF バイト列（該当なしは HTTP 404）。`Content-Length` ヘッダがある場合はクライアントへの応答へ引き継がれる                                                                                                                                                                                                                                                                                                      |

### 環境変数

サーバの動作は環境変数で設定する。`PDF_DEEPLINK_ZOTERO_FILE_PATH` を指定しない場合、または `{key}` を含まない場合は起動に失敗する。

| 環境変数                         | 必須 | 既定値                   | 内容・指定形式                                                                                                                                                                                             |
| -------------------------------- | ---- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PDF_DEEPLINK_ZOTERO_FILE_PATH`  | 必須 | なし                     | PDF ファイルを取得するパスのテンプレート。`{key}` を必ず含む（例: `/api/users/0/items/{key}/file`）。実行時に `{key}` が 8 文字の添付キーへ置換される                                                      |
| `PDF_DEEPLINK_LISTEN`            | 任意 | `127.0.0.1:8787`         | サーバの待ち受け先。`<ホスト>:<ポート>` または Unix ドメインソケット `unix:<パス>` を指定する。Unix ドメインソケットを指定した場合は、起動時に既存の同名ファイルを削除し、パーミッション `0660` で作成する |
| `PDF_DEEPLINK_ALLOWED_HOSTS`     | 任意 | `localhost,127.0.0.1`    | 受け付ける HTTP リクエストの `Host` ヘッダ（ポート番号を除くホスト名、大文字小文字を区別しない）をカンマ区切りで指定する                                                                                   |
| `PDF_DEEPLINK_ZOTERO_ENDPOINT`   | 任意 | `http://127.0.0.1:23119` | 取得元 API の接続先。`http://<ホスト>[:<ポート>]`（パスは `/` のみ）または `unix:<パス>` を指定する                                                                                                        |
| `PDF_DEEPLINK_ZOTERO_API_PATH`   | 任意 | `/api/users/0`           | 取得元 API のベースパス（末尾の `/` は取り除かれる）                                                                                                                                                       |
| `PDF_DEEPLINK_ZOTERO_TIMEOUT_MS` | 任意 | `30000`                  | 取得元への各リクエストのタイムアウト（ミリ秒、正の整数）。超過した場合は HTTP 504 を返す                                                                                                                   |
| `PDF_DEEPLINK_STATIC_DIR`        | 任意 | `dist/`                  | ビルド済みフロントエンド資産の配置ディレクトリ。`index.html` が存在しない場合は静的ファイルを配信せず、API（`/app/` 配下）のみ応答する                                                                     |

### アクセス制限

`pdf-deeplink` 自身は利用者認証やアクセス認可を行わない。サーバへ到達できる利用者は、取得元の全 PDF と書誌情報にアクセスできる。既定ではループバック（`127.0.0.1:8787`）でのみ待ち受けるため、他端末やネットワーク経由で利用する場合は、前段に認証・アクセス制御を担うリバースプロキシや閉域ネットワークを配置すること。

サーバはリクエストごとに次の制限を適用する。

- `Host` ヘッダの制限: `PDF_DEEPLINK_ALLOWED_HOSTS` に含まれないホスト名へのリクエストは HTTP 403 で拒否される。リバースプロキシ経由や別のホスト名で公開する場合は、利用するホスト名を `PDF_DEEPLINK_ALLOWED_HOSTS` へ追加し、プロキシからその `Host` ヘッダを転送すること。
- クロスサイトリクエストの拒否: `Sec-Fetch-Site` ヘッダが `same-origin` および `none` 以外のリクエストは HTTP 403 で拒否される。
- HTTP メソッドの制限: `GET` 以外のリクエストは HTTP 405 で拒否される。

### 起動手順

#### コンテナでの起動

開始条件: Docker 互換のコンテナランタイムが利用でき、コンテナ内から取得元 API へ到達できること。

コンテナ内では `127.0.0.1` がコンテナ自身を指す。ホスト側へポートを公開する場合は `PDF_DEEPLINK_LISTEN` に `0.0.0.0:8787` を指定し、`PDF_DEEPLINK_ZOTERO_ENDPOINT` にコンテナ内から到達可能な接続先またはマウントした Unix ドメインソケットを指定する。コンテナ内のプロセスは非 root ユーザ（`node`）で実行されるため、Unix ドメインソケットを共有する場合はパーミッションを合わせておくこと。

1. `Dockerfile` からイメージをビルドする。ビルド過程でテスト、型検査、フロントエンドのビルドが実行される。

    ```bash
    docker build -t pdf-deeplink .
    ```

1. 環境変数を指定してコンテナを起動する（説明用のコマンド例。`<取得元のホスト>`、`<ポート>`、および `PDF_DEEPLINK_ZOTERO_FILE_PATH` の値は環境に合わせて置き換える）。

    ```bash
    docker run --rm -p 127.0.0.1:8787:8787 \
        -e PDF_DEEPLINK_LISTEN=0.0.0.0:8787 \
        -e PDF_DEEPLINK_ZOTERO_ENDPOINT=http://<取得元のホスト>:<ポート> \
        -e PDF_DEEPLINK_ZOTERO_FILE_PATH=/api/users/0/items/{key}/file \
        pdf-deeplink
    ```

1. 標準出力に `listening on http://0.0.0.0:8787` と出力され、ブラウザで `http://127.0.0.1:8787/` を開いて文献一覧が表示されることを確認する。

#### Node.js での起動

開始条件: Node.js 24 以上が利用でき、取得元 API へ到達できること。

1. 依存パッケージをインストールする。

    ```bash
    npm ci
    ```

1. フロントエンドをビルドし、`dist/` へ出力する。

    ```bash
    npm run build
    ```

1. 環境変数を指定してサーバを起動する（説明用のコマンド例。`PDF_DEEPLINK_ZOTERO_FILE_PATH` の値は取得元の仕様に合わせて置き換える）。

    ```bash
    PDF_DEEPLINK_ZOTERO_FILE_PATH=/api/users/0/items/{key}/file node server/main.ts
    ```

1. 標準出力に `listening on http://127.0.0.1:8787`（Unix ドメインソケット指定時は `listening on unix:<パス>`）と出力され、ブラウザで `http://127.0.0.1:8787/` を開いて文献一覧が表示されることを確認する。

## 開発

### 初期設定

必要なツール: Node.js（バージョンは `.nvmrc` と `mise.toml` に定義）、および Git フックを導入する場合の `uv`。

初期セットアップスクリプトを実行すると、依存パッケージのインストール、`uv` による `pre-commit` の導入、および `pre-commit` / `pre-push` フックの登録が順に実行される。

```bash
bash scripts/setup.sh
```

Git フックを導入せずに依存パッケージだけをインストールする場合は `npm install` を実行する。

### 開発サーバの起動

開発時は API サーバとフロントエンド開発サーバ（Vite）を別々の端末で起動する。Vite は `127.0.0.1:5173` で待ち受け、`/app` へのリクエストを `http://<PDF_DEEPLINK_LISTEN>`（未設定時は `http://127.0.0.1:8787`）へ転送する。Vite の転送先は HTTP を前提とするため、開発サーバ利用時の `PDF_DEEPLINK_LISTEN` には `<ホスト>:<ポート>` 形式を指定すること。

1. API サーバをファイル監視モードで起動する（説明用のコマンド例。`PDF_DEEPLINK_ZOTERO_FILE_PATH` の値は取得元の仕様に合わせて置き換える）。

    ```bash
    PDF_DEEPLINK_ZOTERO_FILE_PATH=/api/users/0/items/{key}/file npm run dev:server
    ```

1. 別の端末でフロントエンド開発サーバを起動する。

    ```bash
    npm run dev:web
    ```

1. ブラウザで `http://127.0.0.1:5173/` を開き、文献一覧が表示されることを確認する。

| `npm run format:check` | Prettier で TypeScript ファイルの書式を検査する                                                                     |
| `npm run format`       | Prettier による整形と ESLint の自動修正を実行する                                                                   |
| `npm run build`        | Vite でフロントエンドを `dist/` へビルドする（PDF.js の付属資産も `dist/pdfjs/` へ複製する）                        |

### 自動検査

Git フック（`.pre-commit-config.yaml`）では、タイミングごとに次の検査が実行される。

- コミット時（`pre-commit`）: シークレット混入の検出（gitleaks）、Markdown・JSON・YAML・TypeScript の整形（Prettier）、Markdown リント（markdownlint-cli2）、ESLint、および末尾空白・改行コード混在・マージ競合・YAML 構文・大容量ファイルの検査
- プッシュ時（`pre-push`）: 型検査（`npm run typecheck`）とテスト（`npm test`）

CI（`.github/workflows/ci.yml`）は `main` ブランチ宛ての Pull Request で自動実行され、Node.js 向けの検査ジョブ（外部の再利用ワークフローを呼び出す構成）と `docker build .` によるコンテナイメージのビルドを検証する。
