# pdf-deeplink

`pdf-deeplink` は、PDF 上の文章や矩形領域を指すリンクを発行し、リンクから該当箇所を開いて強調表示する Web アプリケーションである。ブラウザ上で動作する PDF.js ベースのビューアと、Zotero API v3 互換の取得元へ中継する Node.js HTTP サーバで構成される。

利用する機能と操作は「主な機能」、自身の環境へ配置して起動する方法は「導入」、ローカルでの変更と検証は「開発」を参照のこと。

## 主な機能

トップ画面（`/`）には取得元から PDF が添付された文献が一覧表示され、検索、並び替え、表示件数の変更、ページ送りから対象の PDF をビューア（`/view`）で開ける。ビューアは、箇所リンクの発行、該当箇所の強調表示、PDF の版の照合、出典のコピーを担う。

### 箇所リンクの発行

ビューアのツールバーで選択の方法を「文章」または「範囲」に切り替え、PDF 上の対象箇所を指定するとリンク作成ダイアログが開く。ダイアログで任意の目印を編集し、「リンクをコピー」を押すと、利用中の環境のオリジンを起点とした `/view?...` 形式の URL がクリップボードへコピーされる。クリップボードへ書き込めない場合は、URL が表示されたダイアログから手動でコピーできる。

- 文章: ページ上のテキストをドラッグして選択する。選択したテキスト（先頭 100 文字まで）が目印の初期値として設定される。1 つのリンクで指定できるのは同一ページ内の範囲に限られ、ページをまたぐ選択や上限を超える長い選択では通知が表示されてリンクを作成できないため、ページごとに選択するか範囲を狭める
- 範囲: ページ上をドラッグして矩形領域を指定する。図表やテキスト情報を含まない領域にも利用できる

発行されたリンクはサーバに保存されず、URL のパスとクエリだけで移動先と強調表示する範囲が定まる。配置先のオリジンが変わった場合は、発行済みリンクのオリジンを書き換えて利用できる。リンクに記録されるパラメータや座標系の仕様は [リンク形式の仕様](docs/link-format.md) を参照のこと。

### 該当箇所の強調表示

発行した箇所リンクを開くと、ビューアは PDF をページ幅に合わせて表示し、対象ページの該当箇所へスクロールしたうえで指定された範囲を 8 秒間強調表示する。

リンクの形式に誤りがある場合や PDF を取得できない場合は、画面上部のバナーにエラー内容が表示される。バナーの表示内容をもとに、URL や取得元への接続状態を確認すること。

### PDF の版の照合

ビューアは、開いた PDF の SHA-256 を計算し、リンク作成時点の版と一致するか照合する。

版が一致しない場合も、指定された範囲は強調表示され、PDF が更新されて位置がずれている可能性がある旨の警告バナーが画面上部に表示される。ただし、指定されたページが PDF に存在しない場合は、範囲は強調表示されず、その旨の警告バナーが表示される。

警告バナーには作成時のページと目印が示される。強調表示がずれている場合や表示されない場合は、バナー内のボタンから、そのページへ移動するか目印で PDF 内を検索して該当箇所を確認すること。

### 出典のコピー

リンク作成ダイアログ、または箇所リンクで開いた際のツールバーにある「出典をコピー」から、取得元の書誌情報（著者、発行年、タイトル、掲載誌、DOI）と該当箇所のページ、目印をまとめた文字列をコピーできる。

## 導入

`pdf-deeplink` を自身の環境へ配置し起動するには、取得元の API 要件を満たしたうえで環境変数を設定し、コンテナまたは Node.js で起動する。

### 取得元の要件

`pdf-deeplink` は、Zotero API v3 形式のエンドポイントから文献一覧、書誌情報、PDF ファイル本体を取得する。接続先（`PDF_DEEPLINK_ZOTERO_ENDPOINT`）は `http://<host>[:<port>]` または `unix:<ソケットパス>` を受け付ける。HTTPS やパスを含む URL は指定できないため、取得元とは HTTP または Unix ドメインソケットで接続する構成とし、API のベースパスは `PDF_DEEPLINK_ZOTERO_API_PATH` で別に指定すること。

すべての要求は `GET` メソッドで `Zotero-API-Version: 3` ヘッダを付与して送信される。認証ヘッダの付与やリダイレクトへの追従には対応しないため、取得元は認証なしで直接ステータス `200` を返すよう構成すること。

| 用途             | 要求パス                                                             | 応答の要件                                                                                                                                                                                                                            |
| ---------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文献一覧・検索   | `<apiPath>/items/top`                                                | クエリ `start`、`limit`、`sort`（`dateModified` / `dateAdded` / `title` / `creator` / `date`）、`direction`（`asc` / `desc`）、任意で `q` を受け取り、アイテム配列の JSON を返す。総件数がある場合は応答ヘッダ `Total-Results` で返す |
| 書誌情報         | `<apiPath>/items/<key>`                                              | 8 桁の大文字英数字 `<key>` に対するアイテム JSON を返す（`data.parentItem` で親アイテムを参照する場合は、その親キーも取得対象となる）                                                                                                 |
| PDF ファイル本体 | `PDF_DEEPLINK_ZOTERO_FILE_PATH` の `{key}` を `<key>` へ置換したパス | 対象の PDF バイト列を返す                                                                                                                                                                                                             |

`<apiPath>` の既定値は `/api/users/0`（`PDF_DEEPLINK_ZOTERO_API_PATH` で変更可能）。文献一覧には、単独の PDF 添付アイテムと、`links.attachment` で PDF（`application/pdf`）添付を参照する親アイテムが表示される。

### 環境変数

サーバの設定は環境変数で指定する。

| 変数名                           | 必須 / 既定値                    | 内容                                                                                        |
| -------------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------- |
| `PDF_DEEPLINK_ZOTERO_FILE_PATH`  | 必須                             | PDF ファイル本体を取得するパス。添付キーへ置換する `{key}` を必ず含む                       |
| `PDF_DEEPLINK_LISTEN`            | 任意（`127.0.0.1:8787`）         | サーバの待ち受け先。`<host>:<port>` または `unix:<ソケットパス>` で指定する                 |
| `PDF_DEEPLINK_ALLOWED_HOSTS`     | 任意（`localhost,127.0.0.1`）    | 許可する `Host` ヘッダのホスト名（ポート番号を除く）をカンマ区切りで指定する                |
| `PDF_DEEPLINK_STATIC_DIR`        | 任意（`dist/`）                  | ビルド済みフロントエンドの静的ファイルを配信するディレクトリ                                |
| `PDF_DEEPLINK_ZOTERO_ENDPOINT`   | 任意（`http://127.0.0.1:23119`） | 取得元の接続先。`http://<host>[:<port>]`（パスなし）または `unix:<ソケットパス>` で指定する |
| `PDF_DEEPLINK_ZOTERO_API_PATH`   | 任意（`/api/users/0`）           | 取得元の一覧・書誌情報 API のベースパス                                                     |
| `PDF_DEEPLINK_ZOTERO_TIMEOUT_MS` | 任意（`30000`）                  | 取得元への各要求のタイムアウト（ミリ秒、正の整数）。超過時は `504` を返す                   |

- `PDF_DEEPLINK_LISTEN` に `unix:<ソケットパス>` を指定した場合、起動時に既存のソケットファイルがあれば削除して作成し、パーミッションを `0660` に設定する
- `PDF_DEEPLINK_STATIC_DIR` 配下にビルド済みのフロントエンド（`index.html`）がない場合、画面は配信されず API のみが応答する。画面を含めて利用する場合は、事前にフロントエンドをビルドすること

### アクセス制御

`pdf-deeplink` は利用者認証および認可を行わない。ループバック以外から到達できる環境へ配置する場合は、前段のリバースプロキシやネットワーク境界で認証・アクセス制御と TLS 終端を構成し、利用するホスト名を `PDF_DEEPLINK_ALLOWED_HOSTS` へ追加すること。ビューアはブラウザの Web Crypto API（`crypto.subtle`）で PDF の SHA-256 を計算するため、ループバック以外から開く環境では HTTPS での配信を要する。

サーバ側では、DNS リバインディングや他サイト経由の不正な呼び出しを防ぐため、`PDF_DEEPLINK_ALLOWED_HOSTS` に含まれない `Host` ヘッダの要求とクロスサイト要求を拒否する。また、PDF の URL を直接開かれた場合でも同一オリジン上でインライン実行されないよう、PDF 配信応答へ保護ヘッダを付与する。前段にリバースプロキシを配置する場合は、利用するホスト名が `Host` ヘッダとして届くよう設定し、サーバが付与する応答ヘッダを上書きしないこと。

### 起動手順

#### コンテナでの起動

前提: Docker を利用できること。取得元へコンテナ内から HTTP またはマウントした Unix ドメインソケットで到達できること。

`Dockerfile` のビルドでは依存導入、テスト、型検査、フロントエンドのビルドが実行され、実行ステージでは非 root の `node` ユーザーで `node server/main.ts` が起動する。コンテナ外からポート転送で接続するには、`PDF_DEEPLINK_LISTEN` を `0.0.0.0:8787` のように変更する。

1. リポジトリ直下でコンテナイメージをビルドする。
1. `PDF_DEEPLINK_ZOTERO_FILE_PATH` と接続先を指定してコンテナを起動する。

説明用のコマンド例（`PDF_DEEPLINK_ZOTERO_ENDPOINT` と `PDF_DEEPLINK_ZOTERO_FILE_PATH` は利用する取得元に合わせて置き換える）:

```bash
docker build -t pdf-deeplink .
docker run --rm \
    -p 127.0.0.1:8787:8787 \
    -e PDF_DEEPLINK_LISTEN=0.0.0.0:8787 \
    -e PDF_DEEPLINK_ZOTERO_ENDPOINT=http://192.0.2.10:23119 \
    -e PDF_DEEPLINK_ZOTERO_FILE_PATH='/path/to/items/{key}/file' \
    pdf-deeplink
```

確認方法: コンテナの標準出力に `listening on http://0.0.0.0:8787` が出力され、ブラウザで `http://127.0.0.1:8787` を開くと文献一覧が表示される。

注意: `localhost` と `127.0.0.1` 以外のホスト名でアクセスする場合は、そのホスト名を `PDF_DEEPLINK_ALLOWED_HOSTS` に含めること。Unix ドメインソケットをバインドマウントする場合は、コンテナ内の `node` ユーザーからアクセスできる権限を設定すること。

失敗時の対処: 環境変数の不足や不正な値がある場合は起動直後にエラーを出力して終了する。コンテナのログを確認し、環境変数を修正して再起動する。

#### Node.js での起動

前提: Node.js 24 以上（バージョンは `.nvmrc` と `mise.toml` に記載）を導入していること。取得元へ到達できること。

1. 依存パッケージを導入する（`npm ci`）。
1. フロントエンドをビルドし、`dist/` を生成する（`npm run build`）。
1. 環境変数を設定して `node server/main.ts` を実行する。

説明用のコマンド例（POSIX シェル。`PDF_DEEPLINK_ZOTERO_FILE_PATH` は利用する取得元に合わせて置き換える）:

```bash
npm ci
npm run build
PDF_DEEPLINK_ZOTERO_FILE_PATH='/path/to/items/{key}/file' node server/main.ts
```

確認方法: 標準出力に `listening on http://127.0.0.1:8787`（`PDF_DEEPLINK_LISTEN` を変更した場合はその待ち受け先）が出力され、ブラウザで待ち受け先を開くと文献一覧が表示される。

失敗時の対処: 起動直後にエラーで終了した場合は、Node.js のバージョン（24 以上）と環境変数の指定を確認し、修正して再実行する。

## 開発

開発時は Node.js で API サーバと Vite 開発サーバを並行起動し、テスト、型検査、リント、書式検査、コンテナビルドで変更を検証する。

### 開発環境の準備

前提: Node.js 24 以上。Git フックを一括導入する `scripts/setup.sh` を利用する場合は、Bash と `uv` を導入していること。

- 依存パッケージの導入と Git フックの登録を一括で行う場合: `bash scripts/setup.sh` を実行する（内部で `npm install`、`uv tool install pre-commit`、`uvx pre-commit install --hook-type pre-commit --hook-type pre-push` を実行する）
- 依存パッケージのみ導入する場合: `npm install` を実行する

確認方法: `npm test` を実行し、すべてのテストが通過することを確認する。

### 開発サーバの起動

前提: 依存パッケージの導入と取得元の起動が完了していること。

1. 一方の端末で `PDF_DEEPLINK_ZOTERO_FILE_PATH` を設定し、`npm run dev:server` を実行する。ファイル変更を監視しながら API サーバが既定の `127.0.0.1:8787` で待ち受ける。
1. もう一方の端末で `npm run dev:web` を実行する。Vite 開発サーバが `http://127.0.0.1:5173` で起動し、`/app` への要求を API サーバへ転送する。

確認方法: ブラウザで `http://127.0.0.1:5173` を開くと画面が表示される。

注意: `PDF_DEEPLINK_LISTEN` を既定から変更する場合は、両プロセスに同じ `<host>:<port>` を指定すること。Vite のプロキシは HTTP 接続を前提としているため、`dev:web` 経由の開発では `unix:` 形式の待ち受け先を利用できない。

### 検査

検査およびビルドは `package.json` の npm スクリプトから実行する。

| コマンド               | 内容                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `npm test`             | `node --test` によるテストの実行（`spec/link-vectors.json` と `spec/geometry-vectors.json` を用いたリンク形式と座標変換の検証を含む） |
| `npm run typecheck`    | `tsc --noEmit` による TypeScript の型検査                                                                                             |
| `npm run lint`         | `eslint .` による静的検査                                                                                                             |
| `npm run format:check` | `prettier --check "**/*.{ts,tsx}"` による TypeScript の書式検査                                                                       |
| `npm run format`       | TypeScript の自動整形と ESLint による自動修正                                                                                         |
| `npm run build`        | `vite build` によるフロントエンドの本番ビルド                                                                                         |

Git フック（`.pre-commit-config.yaml` に定義）は、コミット時とプッシュ時にそれぞれの段階に応じた検査を実行する。

- `pre-commit`: シークレット検出（gitleaks）、Prettier（Markdown・JSON・YAML・TypeScript）、markdownlint-cli2、ESLint、行末空白・末尾改行・改行コード混在・マージ競合・YAML 構文・大容量ファイルの検査
- `pre-push`: `npm run typecheck`、`npm test`

CI（`.github/workflows/ci.yml`）では、`main` ブランチ向けの Pull Request を対象に、外部の再利用可能ワークフローを呼び出す `lint-and-test` ジョブと、`docker build .` を実行する `image` ジョブが動作する。
