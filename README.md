# pdf-deeplink

PDF 上で選択した文章や矩形の範囲を指すリンクを発行し、リンクを開くと該当箇所へ移動して範囲を一時的に強調表示する Web アプリである。メモやチャットに貼ったリンクから、どの記述や図を指していたかを後から確認できる。PDF は Zotero Web API v3 互換の API から取得し、PDF にも取得元にも書き込まない。

## 機能

- 文献の一覧: 検索語での絞り込み、更新日・追加日・タイトル・著者・発行年による並び替え、表示件数（20・50・100 件）の選択とページ送り。検索語、並び順、表示件数、ページは URL に保存される
- リンクの発行: 文章のドラッグ、または「範囲」モードで矩形を囲み、ポップアップの「リンクをコピー」でリンクをコピーする。目印（引用、図表番号、メモ）を添えられる
- リンクの表示: リンクを開くと該当ページへ移動し、範囲を一時的に強調表示する。PDF の版が異なる場合は範囲を適用せず、目印を表示する
- 出典のコピー: 著者、発行年、タイトル、掲載誌、DOI、ページ、目印をまとめてコピーする

リンクの形式は [リンクの形式](docs/link-format.md) に定める。

## 構成

| ディレクトリ | 役割                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------- |
| `web/`       | ブラウザ上で動作するビューア。PDF.js で PDF を表示し、範囲の選択、リンクの発行と解釈、強調表示を担う |
| `server/`    | 取得元の API へ問い合わせる API と、ビルドしたビューアの配信を担う Node.js のサーバ                  |
| `shared/`    | ビューアとサーバが共用するリンクの解釈と座標の変換                                                   |
| `spec/`      | リンク形式と座標変換のテストベクタ                                                                   |

## 取得元の API

サーバは、次の要求に応じる HTTP サーバを取得元として用いる。要求には `Zotero-API-Version: 3` ヘッダを付ける。

| 要求                                                                        | 用途                                                                                                      |
| --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `GET <API のパス>/items/top?q=&sort=&direction=&start=&limit=`              | 一覧。応答の `Total-Results` ヘッダで総件数を、各アイテムの `links.attachment` で代表の添付ファイルを得る |
| `GET <API のパス>/items/<アイテムキー>`                                     | 添付ファイルと親アイテムの書誌                                                                            |
| `GET <ファイルのパス>`（`{key}` を添付ファイルのアイテムキーに置き換える） | PDF の本体。状態コード `200` と PDF のバイト列を返すこと                                                  |

Zotero 7 以降のデスクトップアプリが提供する Local API（`http://127.0.0.1:23119/api/users/0`）は、一覧と書誌の要求に応じる。Local API の `items/<キー>/file` は PDF の本体ではなく `file://` へのリダイレクトを返すため、PDF の本体を返す経路は別に用意する必要がある。

一覧には、各アイテムの代表の添付ファイルが PDF であるものだけを表示する。PDF を複数添付したアイテムは、代表の 1 件だけを表示する。

サーバは、検索条件に合う上位アイテムを 100 件ずつすべて取得してから PDF のあるものに絞り込み、総件数とページを求める。結果は同じ検索条件について 60 秒間保持され、ページの移動では取得元へ問い合わせない。1 回の検索で取得する上位アイテムは 5,000 件までとし、それを超える場合は一覧にその旨が表示される。

## 設定

設定は環境変数で指定する。

| 変数                         | 既定値                   | 内容                                                                                     |
| ---------------------------- | ------------------------ | ---------------------------------------------------------------------------------------- |
| `PDF_DEEPLINK_ZOTERO_FILE_PATH`  | なし（必須）             | PDF の本体を返す経路。`{key}` を含めること（例: `/files/{key}`）                         |
| `PDF_DEEPLINK_ZOTERO_ENDPOINT`   | `http://127.0.0.1:23119` | 取得元の接続先。`http://<ホスト>:<ポート>` または `unix:<ソケットのパス>`                |
| `PDF_DEEPLINK_ZOTERO_API_PATH`   | `/api/users/0`           | 取得元の API のパス                                                                      |
| `PDF_DEEPLINK_ZOTERO_TIMEOUT_MS` | `30000`                  | 取得元への 1 回の問い合わせのタイムアウト（ミリ秒）                                      |
| `PDF_DEEPLINK_LISTEN`            | `127.0.0.1:8787`         | 待ち受け先。`<アドレス>:<ポート>` または `unix:<ソケットのパス>`（モード `0660` で作成） |
| `PDF_DEEPLINK_ALLOWED_HOSTS`     | `localhost,127.0.0.1`    | 受け付ける `Host` ヘッダのホスト名（カンマ区切り）                                       |
| `PDF_DEEPLINK_STATIC_DIR`        | ビルド結果の `dist/`     | 配信するビューアのディレクトリ                                                           |

利用者が要求を中断した場合、取得元への問い合わせも打ち切られる。

## 接続元の制限

サーバは、`Host` ヘッダが `PDF_DEEPLINK_ALLOWED_HOSTS` に含まれるホスト名に一致しない要求と、`Sec-Fetch-Site` ヘッダが `same-origin` または `none` 以外の要求を HTTP 403 で拒否する。この制限により、悪意のある Web ページが DNS リバインディングやクロスサイト要求でサーバを呼び出し、ライブラリの内容を読み取ることを防ぐ。リバースプロキシの背後に配置する場合は、利用者がアクセスするホスト名を `PDF_DEEPLINK_ALLOWED_HOSTS` に加えること。

サーバは利用者の認証を行わない。ループバックアドレスや Unix ソケットで待ち受けるか、認証を担うリバースプロキシの背後に配置すること。

## 起動

### コンテナ

```sh
docker build -t pdf-deeplink .
docker run --rm -p 127.0.0.1:8787:8787 \
    -e PDF_DEEPLINK_LISTEN=0.0.0.0:8787 \
    -e PDF_DEEPLINK_ZOTERO_ENDPOINT=http://<取得元のホスト>:<ポート> \
    -e PDF_DEEPLINK_ZOTERO_FILE_PATH='/files/{key}' \
    pdf-deeplink
```

ブラウザで `http://127.0.0.1:8787/` を開く。

### Node.js

[mise](https://mise.jdx.dev/) で `mise.toml` に定義された Node.js を利用する。

```sh
mise exec -- npm ci
mise exec -- npm run build
PDF_DEEPLINK_ZOTERO_FILE_PATH='/files/{key}' mise exec -- node server/main.ts
```

## 開発

ビューアの開発サーバ（Vite）は `http://127.0.0.1:5173/` で待ち受け、`/app/` への要求をサーバへ中継する。サーバとビューアの開発サーバを、別々の端末で起動する。

```sh
PDF_DEEPLINK_ZOTERO_FILE_PATH='/files/{key}' mise exec -- npm run dev:server
mise exec -- npm run dev:web
```

開発サーバは、PDF.js が実行時に取得する CMap、標準フォント、Wasm、ICC プロファイルを、`node_modules/pdfjs-dist` から `/pdfjs/` 配下で配信する。`npm run build` は同じ構成で `dist/pdfjs/` に複製する。

検査は次のコマンドで実行する。CI も同じ検査とイメージのビルドを実行する。

```sh
mise exec -- npm test
mise exec -- npm run typecheck
```
